# 国际化功能实施文档

本文面向一个全新的 React + TypeScript 前端项目，提供一套可以直接落地的国际化实施方案。完成全部步骤后，项目将支持：

- 中文和英文切换；
- 浏览器语言自动检测；
- 刷新页面后保留语言选择；
- 按业务域拆分翻译资源；
- React 组件和非 React 模块使用翻译；
- 菜单、路由标题、面包屑、标签页、表格、表单错误和提示消息国际化；
- 日期、数字和图表日期根据语言显示；
- VS Code 辅助编辑翻译资源；
- 翻译 key 和插值变量一致性检查。

本文默认使用 pnpm。使用 npm 或 Yarn 时，将命令替换为对应包管理器命令，并在项目中只保留一种 lockfile。

## 一、先确定实施方案

### 1. 技术选型

采用以下工具：

| 能力         | 工具                                                  |
| ------------ | ----------------------------------------------------- |
| 翻译核心     | `i18next`                                             |
| React 集成   | `react-i18next`                                       |
| 初始语言检测 | `i18next-browser-languagedetector`                    |
| 状态持久化   | Redux Toolkit + `redux-persist`                       |
| 日期本地化   | `date-fns`、`react-day-picker` 或项目正在使用的日期库 |
| 编辑器辅助   | VS Code i18n Ally                                     |

翻译资源直接打包进前端，不依赖接口或 CDN。这样实现简单、切换速度快，适合管理后台和中小型应用。如果资源非常大，再考虑使用 `i18next-http-backend` 动态加载，不能在两种加载方案之间混用同一份初始化配置。

### 2. 语言和命名空间约定

本指南初始支持两种语言：

- `en`：英文，也是默认语言和回退语言；
- `zh`：中文。

资源按命名空间拆分：

- `common`：通用按钮、状态、文件和设置文案；
- `auth`：登录、注册和身份认证文案；
- `menu`：菜单、路由和图表导航文案；
- `header`：顶部导航区域文案。

翻译调用规则：

```text
common 命名空间：t('confirm')
其他命名空间：t('auth:login.title')、t('menu:dashboard.title')
```

key 使用稳定的英文路径，不使用中文作为 key。翻译文本可以随语言变化，业务代码中的 key 不应随文案调整而变化。

### 3. 语言状态的唯一规则

语言切换会涉及两个状态：

1. i18next 的当前语言，决定 `t()` 返回什么文本；
2. Redux 中的语言，决定应用设置和持久化状态。

切换时必须同时更新两者。应用启动时，应先恢复持久化状态，再将 Redux 语言同步到 i18next，避免首屏出现中文、随后闪成英文的情况。

## 四、初始化 i18next

### 步骤 7：创建 i18next 单例

创建 `src/features/lang/index.ts`：

```ts
import i18n from "i18next";
import LanguageDetector from "i18next-browser-languagedetector";
import { initReactI18next } from "react-i18next";
import { DEFAULT_LANGUAGE } from "./config";
import { resources } from "./locales";

void i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources,
    lng: undefined,
    fallbackLng: DEFAULT_LANGUAGE,
    supportedLngs: ["en", "zh"],
    ns: ["common", "auth", "menu", "header"],
    defaultNS: "common",
    interpolation: {
      escapeValue: false,
    },
    detection: {
      order: ["localStorage", "navigator", "htmlTag", "path", "subdomain"],
      caches: ["localStorage"],
    },
  });

export default i18n;
```

配置说明：

- `resources` 使用本地 JSON，应用构建时一并打包。
- `fallbackLng` 指定缺失翻译时的回退语言。
- `supportedLngs` 限制可以被应用接受的语言，避免浏览器返回未实现的语言代码。
- `ns` 必须包含所有实际使用的命名空间；资源里有 `header` 时，不要忘记在这里声明。
- `defaultNS: 'common'` 使 `t('confirm')` 默认查找 `common`。
- `escapeValue: false` 是 React 项目的常用配置，因为 React 渲染文本时会进行转义。不要把翻译结果直接当作不可信 HTML 插入页面。
- `detection.order` 按顺序检测 localStorage、浏览器语言、HTML lang、路径和子域名。
- `caches` 将用户选择保存到浏览器 localStorage。

如果要使用 HTTP 动态资源，就不要传入本地 `resources`，而应安装并配置 `i18next-http-backend`，并处理加载中和加载失败状态。本指南采用本地资源方案。

### 步骤 8：在入口文件加载 i18n

在 `src/main.tsx` 或应用真正的入口文件中，在渲染根组件前导入 i18n：

```tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import "@/features/lang";
import App from "./App";
import "./index.css";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <App />
  </StrictMode>,
);
```

如果项目没有 `@/` 路径别名，改用相对路径。该导入的作用是执行初始化代码，不能删除或延后到某个页面内部，否则首屏组件可能在 i18next 初始化前渲染。

本方案使用全局 i18next 单例，因此不需要额外的 `I18nextProvider`。如果项目希望创建多个 i18next 实例，则必须显式使用 `I18nextProvider`，并保证所有组件使用同一个实例。

```bash

```

## 五、接入 Redux 持久化语言状态

如果项目不使用 Redux，可以跳过本节，只使用 i18next detector 保存语言。已有 Redux 项目建议完成本节，使语言和其他应用设置保持一致。

### 步骤 10：在应用状态中增加 language

创建或修改 `src/store/modules/app.ts`：

```ts
import type { PayloadAction } from "@reduxjs/toolkit";
import { createSlice } from "@reduxjs/toolkit";
import type { Language } from "@/features/lang/config";

interface AppState {
  language: Language | null;
}

const initialState: AppState = {
  language: null,
};

const appSlice = createSlice({
  name: "app",
  initialState,
  reducers: {
    setLanguage(state, action: PayloadAction<Language | null>) {
      state.language = action.payload;
    },
  },
  selectors: {
    selectLanguage: (state) => state.language,
  },
});

export const { setLanguage } = appSlice.actions;
export const { selectLanguage } = appSlice.selectors;
export const appActions = appSlice.actions;
export const appSelectors = appSlice.selectors;
export default appSlice.reducer;
```

将 `language` 类型限定为 `Language`，避免 dispatch 一个没有资源的代码。

### 步骤 11：配置 redux-persist

创建或修改 `src/store/index.ts`：

```ts
import { combineReducers, configureStore } from "@reduxjs/toolkit";
import { persistReducer, persistStore } from "redux-persist";
import storage from "redux-persist/lib/storage";
import appReducer from "./modules/app";

const appPersistedReducer = persistReducer(
  {
    key: "app",
    storage,
    version: 1,
  },
  appReducer,
);

const rootReducer = combineReducers({
  app: appPersistedReducer,
});

export const store = configureStore({
  reducer: rootReducer,
});

export const persistor = persistStore(store);

export type RootState = ReturnType<typeof store.getState>;
export type AppDispatch = typeof store.dispatch;
```

如果项目已有 root reducer，只把 `appPersistedReducer` 放入现有 reducer，不要覆盖其他模块。`redux-persist` 会将语言和 app 状态写入 localStorage。

### 步骤 12：添加 StoreProvider 和 PersistGate

创建 `src/features/store/StoreProvider.tsx`：

```tsx
import { Provider as ReduxProvider } from "react-redux";
import { PersistGate } from "redux-persist/integration/react";
import { persistor, store } from "@/store";

export function StoreProvider({ children }: { children: React.ReactNode }) {
  return (
    <ReduxProvider store={store}>
      <PersistGate loading={<div>Loading...</div>} persistor={persistor}>
        {children}
      </PersistGate>
    </ReduxProvider>
  );
}
```

在入口中将应用包在 `StoreProvider` 内：

```tsx
<StrictMode>
  <StoreProvider>
    <App />
  </StoreProvider>
</StrictMode>
```

`PersistGate` 的 loading 界面应使用项目实际的加载组件。它可以防止 Redux 尚未恢复时，页面先按照初始语言渲染。

### 步骤 13：创建语言同步 Provider

创建 `src/features/lang/LanguageProvider.tsx`：

```tsx
import { useEffect } from "react";
import { useAppDispatch, useAppSelector } from "@/store/hooks";
import { appActions, appSelectors } from "@/store/modules/app";
import i18n from "./index";

export function LanguageProvider({ children }: { children: React.ReactNode }) {
  const dispatch = useAppDispatch();
  const language = useAppSelector(appSelectors.selectLanguage);

  useEffect(() => {
    if (language && i18n.language !== language) {
      void i18n.changeLanguage(language);
    }
  }, [language]);

  useEffect(() => {
    const handleLanguageChanged = (nextLanguage: string) => {
      if (nextLanguage === language) {
        return;
      }

      if (nextLanguage === "en" || nextLanguage === "zh") {
        dispatch(appActions.setLanguage(nextLanguage));
      }
    };

    i18n.on("languageChanged", handleLanguageChanged);
    return () => i18n.off("languageChanged", handleLanguageChanged);
  }, [dispatch, language]);

  return <>{children}</>;
}
```

如果项目已经有类型化的 `useAppDispatch` 和 `useAppSelector`，使用它们；否则可以使用 React Redux 的基础 hooks，但应为 `RootState` 和 `AppDispatch` 提供类型。

在 `App.tsx` 中放到需要翻译的内容外层：

```tsx
export default function App() {
  return (
    <LanguageProvider>
      <RouterProvider router={router} />
    </LanguageProvider>
  );
}
```

Provider 需要在 `RouterProvider` 或页面布局外层，确保所有路由组件都能在语言变化时重新渲染。

## 六、实现语言切换

### 步骤 14：创建无 UI 依赖的语言切换函数

为了避免每个组件重复实现同步逻辑，创建 `src/features/lang/changeLanguage.ts`：

```ts
import type { Language } from "./config";
import i18n from "./index";

export async function changeLanguage(language: Language) {
  await i18n.changeLanguage(language);
}
```

如果 `LanguageProvider` 已监听 `languageChanged`，切换函数只需要调用 i18next；事件监听会将新语言写入 Redux。也可以显式 dispatch，但不要同时采用两种方式，以免重复更新。

### 步骤 15：创建语言选择器

创建 `src/features/lang/LanguageSwitcher.tsx`。下面使用原生 `select`，不依赖具体 UI 组件库：

```tsx
import { useTranslation } from "react-i18next";
import { useAppSelector } from "@/store/hooks";
import { appSelectors } from "@/store/modules/app";
import { DEFAULT_LANGUAGE, LANGUAGE_RECORDS } from "./config";
import type { Language } from "./config";
import { changeLanguage } from "./changeLanguage";
import i18n from "./index";

export function LanguageSwitcher() {
  const { t } = useTranslation();
  const storedLanguage = useAppSelector(appSelectors.selectLanguage);
  const currentLanguage = storedLanguage || i18n.language || DEFAULT_LANGUAGE;

  return (
    <label>
      <span className="sr-only">{t("changeLanguage")}</span>
      <select
        value={currentLanguage}
        onChange={(event) => {
          void changeLanguage(event.target.value as Language);
        }}
      >
        {LANGUAGE_RECORDS.map((language) => (
          <option key={language.code} value={language.code}>
            {language.name}
          </option>
        ))}
      </select>
    </label>
  );
}
```

如果项目使用 Dropdown、RadioGroup 或其他组件库，只替换 UI 部分，保留以下规则：

1. 选项来自 `LANGUAGE_RECORDS`。
2. value 使用语言代码，不使用显示名称。
3. 切换前确认该语言存在于资源对象。
4. `changeLanguage` 使用异步调用并处理失败。
5. 切换完成后，页面和持久化状态都使用同一个语言。

### 步骤 16：验证持久化和切换竞态

按以下顺序验证：

1. 打开页面，选择中文。
2. 等待页面文本变化后刷新浏览器。
3. 确认仍是中文。
4. 打开 DevTools，确认 i18next 的语言缓存和 Redux Persist 的 app 状态没有互相覆盖。
5. 清除 localStorage 后刷新，确认浏览器语言检测和默认语言生效。
6. 选择英文后，在开发者工具中快速刷新多次，确认没有闪回中文。

如果使用 Redux Persist 和 i18next detector 双重保存，建议让 `LanguageProvider` 在恢复完成后以 Redux 状态为准；如果不需要 Redux，则只保留 i18next detector，减少状态来源。

## 七、在业务代码中使用翻译

### 步骤 17：React 组件使用 `useTranslation`

```tsx
import { useTranslation } from "react-i18next";

export function LoginPanel() {
  const { t } = useTranslation();

  return (
    <section>
      <h1>{t("auth:login.title")}</h1>
      <label>{t("auth:common.username")}</label>
      <input placeholder={t("auth:common.inputUsername")} />
      <button>{t("auth:common.login")}</button>
    </section>
  );
}
```

通用命名空间可以省略前缀：

```tsx
const { t } = useTranslation()

<button>{t('confirm')}</button>
<p>{t('file.selectedFiles', { count: selectedFiles.length })}</p>
```

### 步骤 18：处理插值和复数文案

带变量的翻译必须传入对象：

```tsx
<p>{t("file.maxFiles", { count: 5 })}</p>
```

不要直接拼接不同语言的句子：

```tsx
// 不推荐
<p>{count} 个文件已选择</p>

// 推荐
<p>{t('file.selectedFiles', { count })}</p>
```

如果一个语言需要复数变化，应按 i18next 的 plural 规则设计资源 key，并使用 `count` 参数。不同语言的复数规则不要在组件中用 `if` 手动拼接。

### 步骤 19：将菜单和路由标题保存为 key

菜单配置应保存翻译 key：

```tsx
const { t } = useTranslation();

const menuItems = useMemo(
  () => [
    {
      path: "/dashboard",
      title: t("menu:dashboard.title"),
    },
  ],
  [t],
);
```

路由元数据也保存 key，而不是保存已经翻译的文本：

```ts
{
  path: '/dashboard',
  handle: {
    title: 'menu:dashboard.title',
  },
}
```

面包屑渲染时再执行：

```tsx
const { t } = useTranslation();

return <span>{t(String(route.handle?.title))}</span>;
```

这样切换语言后，菜单和面包屑可以重新计算。不要在路由模块加载时执行一次 `t()` 并永久保存结果。

如果项目有可关闭的路由标签页，标签页状态可能保存的是已翻译文本。语言切换时应根据 path 重新查询菜单标题并同步标签页：

```tsx
useEffect(() => {
  setTabs((tabs) =>
    tabs.map((tab) => ({
      ...tab,
      title: t(tab.titleKey),
    })),
  );
}, [t]);
```

更稳妥的做法是标签页状态保存 `titleKey`，渲染时再翻译；只有在现有数据结构必须保存文本时，才需要切换语言后批量重建标题。

### 步骤 20：非 React 模块使用共享函数

Redux slice、路由工具、表格列工厂和其他非 React 模块不能调用 hook。创建 `src/features/lang/shared.ts`：

```ts
import type { TOptions } from "i18next";
import i18n from "./index";

export function translate(
  key: string,
  options?: TOptions | Record<string, unknown>,
): string {
  return i18n.t(key, options);
}

export default translate;
```

使用方式：

```ts
import { translate } from "@/features/lang/shared";

const defaultTab = {
  title: translate("menu:home"),
  path: "/home",
};
```

直接调用 `i18n.t` 不会自动触发 React 重渲染。对于会随语言变化的内容，优先在组件中使用 `useTranslation`；如果必须在模块状态中保存文本，就在 `languageChanged` 后重新计算。

### 步骤 21：让表格列响应语言

列定义接收 `TFunction`：

```tsx
import type { TFunction } from "i18next";

export function createColumns(t: TFunction) {
  return [
    {
      id: "username",
      header: t("table.username"),
    },
    {
      id: "actions",
      header: t("table.actions"),
    },
  ];
}
```

组件中重新生成列：

```tsx
const { t } = useTranslation();

const columns = useMemo(() => createColumns(t), [t]);
```

不要在模块顶层执行 `createColumns(translate)` 并永久缓存结果，否则切换语言后表头仍会使用旧语言。

### 步骤 22：让表单校验消息响应语言

以 Zod 和 React Hook Form 为例：

```tsx
const { t, i18n } = useTranslation();

const schema = useMemo(
  () =>
    z.object({
      username: z.string().min(1, t("auth:common.usernameRequired")),
      password: z
        .string()
        .min(6, t("auth:login.passwordMinLength", { count: 6 })),
    }),
  [t],
);

useEffect(() => {
  if (form.formState.isDirty) {
    void form.trigger();
  }
}, [form, i18n.language]);
```

关键点：

- schema 依赖 `t` 或 `i18n.language`，语言变化后重新创建；
- 已经显示的错误需要重新触发校验；
- Toast、Dialog、API 错误和上传提示在显示时调用 `t`；
- 不要在模块加载时把翻译结果放进一个永久常量。

## 八、日期、数字和图表本地化

### 步骤 23：配置日期 locale

文本翻译和日期格式是两件事。日期选择器需要单独传入 locale：

```tsx
import { enUS, zhCN } from "date-fns/locale";
import { useTranslation } from "react-i18next";

const localeMap = {
  en: enUS,
  zh: zhCN,
};

export function LocalizedCalendar() {
  const { i18n } = useTranslation();
  const locale = localeMap[i18n.language as keyof typeof localeMap] || enUS;

  return <Calendar locale={locale} />;
}
```

如果组件库使用 `react-day-picker/locale`，从该包导入对应 locale。新增语言时必须扩展 `localeMap`。

### 步骤 24：配置浏览器日期和数字格式

```tsx
const localeMap = {
  en: "en-US",
  zh: "zh-CN",
};

const browserLocale =
  localeMap[i18n.language as keyof typeof localeMap] || "en-US";

const dateText = new Date(value).toLocaleDateString(browserLocale, {
  year: "numeric",
  month: "short",
  day: "numeric",
});

const numberText = value.toLocaleString(browserLocale);
```

不要只切换 JSON 文案而忽略日期、数字、货币和排序规则。日期组件应使用同一个语言来源，避免 Redux 是中文而 i18next 是英文时出现不一致。

## 九、配置 VS Code i18n Ally

### 步骤 25：安装扩展并推荐给团队

在 VS Code 安装 **i18n Ally**。也可以创建 `.vscode/extensions.json`：

```json
{
  "recommendations": ["lokalise.i18n-ally"]
}
```

扩展是辅助工具，不参与生产运行。没有安装扩展的开发者仍可通过 JSON 和命令行完成翻译。

### 步骤 26：配置资源路径和解析方式

在 `.vscode/settings.json` 中加入：

```jsonc
{
  "i18n-ally.displayLanguage": "zh",
  "i18n-ally.enabledParsers": ["ts", "json"],
  "i18n-ally.enabledFrameworks": ["react-i18next"],
  "i18n-ally.editor.preferEditor": true,
  "i18n-ally.keystyle": "nested",
  "i18n-ally.namespace": true,
  "i18n-ally.defaultNamespace": "common",
  "i18n-ally.pathMatcher": "{locale}/{namespace}.json",
  "i18n-ally.localesPaths": ["src/features/lang/locales"],
  "i18n-ally.sourceLanguage": "en",
}
```

这些设置与目录结构的对应关系如下：

```text
{locale}     → en 或 zh
{namespace}  → common、auth、menu、header
localesPaths → src/features/lang/locales
```

打开 TSX 文件后，扩展应能识别 `t('auth:login.title')`；打开 JSON 文件后，应能定位对应翻译。若识别不到 key，先确认路径匹配器和资源目录是否一致。

## 十、翻译资源一致性检查

### 步骤 27：建立手动检查标准

新增或修改翻译后，至少检查：

1. 每个语言都有相同的 namespace 文件。
2. namespace 内 key 路径一致。
3. 插值变量一致。
4. 代码调用的 key 真实存在。
5. 翻译没有把 HTML、业务逻辑或组件代码写进 JSON。
6. 长文本在所有语言下不会破坏按钮、菜单和表格布局。

### 步骤 28：加入简单的 key 对比脚本

对于正式项目，可以增加 `scripts/check-i18n.mjs`。下面的脚本递归比较英文和中文 JSON 的叶子 key：

```js
import fs from "node:fs";
import path from "node:path";

const root = path.resolve("src/features/lang/locales");
const namespaces = ["common", "auth", "menu", "header"];
const languages = ["en", "zh"];

function readJson(language, namespace) {
  const file = path.join(root, language, `${namespace}.json`);
  return JSON.parse(fs.readFileSync(file, "utf8"));
}

function collectKeys(value, prefix = "", result = new Set()) {
  for (const [key, child] of Object.entries(value)) {
    const fullKey = prefix ? `${prefix}.${key}` : key;
    if (child && typeof child === "object" && !Array.isArray(child)) {
      collectKeys(child, fullKey, result);
    } else {
      result.add(fullKey);
    }
  }
  return result;
}

let failed = false;

for (const namespace of namespaces) {
  const languageKeys = Object.fromEntries(
    languages.map((language) => [
      language,
      collectKeys(readJson(language, namespace)),
    ]),
  );
  const baseline = languageKeys.en;

  for (const language of languages.slice(1)) {
    const missing = [...baseline].filter(
      (key) => !languageKeys[language].has(key),
    );
    const extra = [...languageKeys[language]].filter(
      (key) => !baseline.has(key),
    );

    if (missing.length || extra.length) {
      failed = true;
      console.error(`[${namespace}] ${language}`);
      if (missing.length) console.error("missing:", missing.join(", "));
      if (extra.length) console.error("extra:", extra.join(", "));
    }
  }
}

if (failed) {
  process.exit(1);
}

console.log("i18n resource keys are consistent");
```

在 `package.json` 添加：

```json
{
  "scripts": {
    "i18n:check": "node scripts/check-i18n.mjs"
  }
}
```

运行：

```bash
pnpm i18n:check
```

该脚本只能检查资源文件之间的 key，不能保证代码中没有拼错 key；代码调用检查仍需要编辑器、运行时验证或额外的类型化资源方案。

## 十一、完整验证流程

### 步骤 29：执行静态检查和构建

按照项目真实的 scripts 执行：

```bash
pnpm lint
pnpm typecheck
pnpm i18n:check
pnpm build
```

没有 TypeScript、lint、typecheck 或 build 脚本时，跳过不存在的命令，并先在 `package.json` 中配置项目实际使用的命令。不要把一个没有安装的测试命令写进 Git hook。

### 步骤 30：执行功能验证

按以下顺序手动验证：

1. 清空 localStorage，首次打开应用，确认默认语言和浏览器语言检测符合预期。
2. 选择中文，确认页面标题、按钮、菜单、面包屑和顶部区域切换。
3. 选择英文并刷新，确认语言仍为英文。
4. 打开登录页，输入错误内容，确认校验消息使用当前语言。
5. 切换语言后再次检查已经显示的校验消息是否更新。
6. 打开表格，确认列标题、操作按钮和空状态切换。
7. 打开图表，确认图例、标题、提示框、日期和数字格式切换。
8. 打开日期选择器，确认月份、星期和日期格式切换。
9. 打开多个路由标签，切换语言，确认已有标签标题也切换。
10. 访问异常页、重定向页和权限页，检查是否存在固定中文或英文。
11. 关闭浏览器重新打开，确认选择语言仍然保留。
12. 使用不同浏览器语言重新验证首次访问行为。

## 十二、常见问题排查

### 1. 页面显示 `menu:dashboard.title`

检查：

- `menu.json` 是否存在 `dashboard.title`；
- 当前语言的 `index.ts` 是否导出了 `menu`；
- `locales/index.ts` 是否导出了当前语言；
- `i18n.init` 的 `ns` 是否包含 `menu`；
- 调用是否误写成 `t('menu.dashboard.title')`，命名空间分隔符应为 `:`；
- 当前语言是否在 `supportedLngs` 中。

### 2. 语言选择后页面没有变化

检查：

- 入口是否加载 i18n；
- 组件是否使用 `useTranslation`，而不是模块级固定文本；
- 语言选择器是否调用了 `i18n.changeLanguage`；
- `LanguageProvider` 是否位于路由和页面外层；
- 是否在切换后重新生成了菜单、表格列和表单 schema。

### 3. 刷新后语言被覆盖

检查：

- 是否同时启用了 i18next detector 和 Redux Persist；
- 两者是否保存了不同语言；
- `LanguageProvider` 是否在 Redux 恢复后同步 i18next；
- Redux Persist 是否包住了应用；
- localStorage 中是否存在旧版本语言值。

开发期间可以清理 localStorage 后重新验证：

```js
localStorage.clear();
location.reload();
```

### 4. 日期语言没有变化

翻译 JSON 不会自动改变日期库 locale。检查日期组件是否使用 `i18n.language` 或 Redux 语言选择了正确的 locale，并确认新增语言时扩展了映射表。

### 5. 表单错误仍显示旧语言

表单 schema 通常只创建一次。将 schema 放进 `useMemo` 并依赖 `t`，语言变化后调用 `form.trigger()` 重新生成错误消息。

### 6. 菜单变了，标签页没变

标签页可能保存了已翻译的文本。建议状态中保存 `titleKey`，渲染时调用 `t(titleKey)`；如果只能保存 title，则在语言变化后根据路径重新生成标签标题。

### 7. i18n Ally 找不到资源

检查 `.vscode/settings.json` 中的：

- `i18n-ally.localesPaths` 是否指向资源根目录；
- `i18n-ally.pathMatcher` 是否符合 `{locale}/{namespace}.json`；
- 是否安装了 `react-i18next` framework 支持；
- namespace 和嵌套 key 设置是否与 JSON 结构一致。

## 十三、新增一条翻译的标准流程

以新增“导出成功”为例：

1. 在英文 `common.json` 增加：

   ```json
   { "exportSuccess": "Export successful" }
   ```

2. 在中文 `common.json` 增加：

   ```json
   { "exportSuccess": "导出成功" }
   ```

3. 在组件中调用：

   ```tsx
   const { t } = useTranslation();
   toast.success(t("exportSuccess"));
   ```

4. 如果文案属于菜单或认证域，放入对应 namespace，并使用完整调用路径。
5. 如果文案用于表格列、表单 schema、路由标签或 Redux 初始值，确认语言切换后会重新计算。
6. 执行 `pnpm i18n:check`、lint、类型检查和构建。
7. 手动切换所有支持语言，确认文案、插值和布局均正常。
