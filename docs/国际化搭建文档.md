# 国际化搭建文档

本文提炼本项目现有的国际化实现，说明它采用的技术方案、目录组织、语言切换流程，以及从零搭建同类功能时应执行的步骤。示例以 React + TypeScript 项目为基础，代码路径使用本项目的组织方式。

## 一、实现方案总览

本项目使用以下组合完成国际化：

- `i18next`：管理语言资源、当前语言、回退语言、命名空间和插值。
- `react-i18next`：通过 `useTranslation` 将翻译能力接入 React 组件。
- `i18next-browser-languagedetector`：按浏览器和本地存储自动检测初始语言。
- Redux Toolkit + `redux-persist`：保存应用当前语言，并与 i18next 当前语言同步。
- `date-fns`、`react-day-picker` 和浏览器 `Intl`：根据当前语言显示日期和图表日期。
- VS Code i18n Ally：辅助识别和编辑 TypeScript、JSON 中的翻译内容。

整体数据流如下：

```text
语言资源 JSON
    ↓
按语言聚合 resources
    ↓
i18next 初始化（检测初始语言）
    ↓
react-i18next 提供 useTranslation / t
    ↓
页面、布局、表单、菜单、提示消息使用翻译 key

语言选择器
    ↓
i18n.changeLanguage()
    ↓
Redux app.language 持久化
    ↓
菜单、面包屑、标签页、日期组件重新计算
```

本项目将资源直接打包进前端，没有使用 HTTP 动态加载。虽然依赖中存在 `i18next-http-backend`，当前实现没有导入或配置它。

## 二、现有目录和职责

国际化功能集中在 `src/features/lang/`：

```text
src/features/lang/
├── config.ts                    # 默认语言和可选语言列表
├── index.ts                     # 创建并初始化 i18next 单例
├── LanguageProvider.tsx         # 同步 Redux 与 i18next
├── LanguageDropMenu.tsx         # 语言选择下拉菜单
├── shared.ts                    # 非 React 代码使用的翻译函数
└── locales/
    ├── index.ts                 # 聚合所有语言资源
    ├── en/
    │   ├── index.ts             # 聚合英文命名空间
    │   ├── common.json
    │   ├── auth.json
    │   ├── menu.json
    │   └── header.json
    └── zh/
        ├── index.ts             # 聚合中文命名空间
        ├── common.json
        ├── auth.json
        ├── menu.json
        └── header.json
```

命名空间目前按职责划分：

| 命名空间 | 内容                                               |
| -------- | -------------------------------------------------- |
| `common` | 通用按钮、状态、文件、表格、表单、设置、时间等文案 |
| `auth`   | 登录、注册及认证相关文案                           |
| `menu`   | 菜单名称、图表名称和仪表盘菜单文案                 |
| `header` | 顶部区域相关文案                                   |

每种语言必须拥有相同的目录结构和可用 key。翻译值可以不同，但 key 的层级应保持一致，否则切换语言时会出现 key 文本、回退语言或空文案。

## 三、依赖安装

在已有 React/TypeScript 项目的根目录执行：

```bash
pnpm add i18next react-i18next i18next-browser-languagedetector
pnpm add -D @types/i18next
```

如果还要实现本项目中的日期本地化和状态管理：

```bash
pnpm add date-fns react-day-picker
pnpm add @reduxjs/toolkit react-redux redux-persist
```

如果项目使用 npm 或 Yarn，将 `pnpm` 替换为对应命令；不要在同一个项目中混用多个包管理器的 lockfile。

## 四、搭建步骤

### 步骤 1：定义支持的语言

创建 `src/features/lang/config.ts`：

```ts
type Language = "en" | "zh";

interface LanguageRecord {
  code: Language;
  name: string;
}

export const DEFAULT_LANGUAGE: Language = "en";

export const LANGUAGE_RECORDS: LanguageRecord[] = [
  { code: "zh", name: "中文" },
  { code: "en", name: "English" },
];
```

本项目的类型中还预留了 `ja`、`fr`、`de`、`es`、`ru`、`ko`、`it`、`pt`，但 `LANGUAGE_RECORDS` 和实际资源目前只有中文、英文。因此，新增语言不能只扩展类型，还必须同步增加：

1. 语言选择列表；
2. 对应的资源目录和 JSON；
3. `locales/index.ts` 的资源聚合；
4. 日期、数字等本地化映射；
5. 页面手动验证范围。

### 步骤 2：建立语言资源文件

为每种语言创建相同的命名空间文件。例如 `src/features/lang/locales/en/common.json`：

```json
{
  "appTitle": "Shadmin",
  "changeLanguage": "change language",
  "confirm": "confirm",
  "cancel": "cancel",
  "file": {
    "selectedFiles": "Selected files ({{count}})",
    "maxFiles": "A maximum of {{count}} files can be uploaded"
  }
}
```

中文文件使用相同 key：

```json
{
  "appTitle": "Shadmin",
  "changeLanguage": "切换语言",
  "confirm": "确认",
  "cancel": "取消",
  "file": {
    "selectedFiles": "已选择文件 ({{count}})",
    "maxFiles": "最多支持上传 {{count}} 个文件"
  }
}
```

实现约定：

- key 使用稳定的英文路径，不把中文直接当作 key。
- 按业务域组织嵌套对象，例如 `table.editUser`、`form.inputUsername`。
- 带变量的文案统一使用 `{{变量名}}`，调用时通过第二个参数传值。
- 所有语言保持 key 结构一致。
- 修正 key 拼写后要同步修改所有语言文件和所有调用位置；例如现有公共资源中的 `oprationSuccess`、`oprationFailed` 已经被使用，不能只修改一侧。
- 资源 JSON 只保存文案，不放业务判断和 JSX。

### 步骤 3：为每种语言聚合命名空间

创建 `src/features/lang/locales/en/index.ts`：

```ts
import auth from "./auth.json";
import common from "./common.json";
import header from "./header.json";
import menu from "./menu.json";

export default {
  common,
  auth,
  menu,
  header,
};
```

`zh/index.ts` 使用完全相同的导出结构，只从中文目录导入文件。然后在 `src/features/lang/locales/index.ts` 聚合语言：

```ts
import enResource from "./en";
import zhResource from "./zh";

export const resources = {
  zh: zhResource,
  en: enResource,
};
```

资源最终会形成如下结构：

```ts
{
  zh: { common, auth, menu, header },
  en: { common, auth, menu, header },
}
```

语言代码必须与 `Language`、语言选择器和资源对象的 key 完全一致。

### 步骤 4：初始化 i18next

创建 `src/features/lang/index.ts`：

```ts
import i18n from "i18next";
import LanguageDetector from "i18next-browser-languagedetector";
import { initReactI18next } from "react-i18next";
import { resources } from "./locales";

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources,
    fallbackLng: "en",
    ns: ["common", "auth", "menu"],
    defaultNS: "common",
    interpolation: {
      escapeValue: false,
    },
    detection: {
      order: ["localStorage", "navigator", "htmlTag", "path", "subdomain"],
      caches: ["localStorage"],
    },
  });

export default i18n;
```

配置含义：

- `resources` 使用本地导入的 JSON，不依赖网络请求。
- `fallbackLng: 'en'` 表示当前语言缺少 key 时回退到英文。
- `defaultNS: 'common'` 表示 `t('confirm')` 等未带命名空间的 key 默认从 `common` 查找。
- `ns` 声明常用命名空间；使用 `t('auth:login.login')`、`t('menu:home')` 时通过 `命名空间:key` 指定资源域。
- `escapeValue: false` 适用于 React，因为 React 默认会转义文本；如果将翻译结果直接插入 HTML，必须另外处理 XSS 风险。
- `detection.order` 优先读取浏览器本地存储，其次读取浏览器语言和其他来源。
- `caches: ['localStorage']` 会将检测到的语言写入本地存储，刷新后保留选择。

当前资源中还存在 `header` 命名空间，但初始化的 `ns` 列表没有写入 `header`。如果项目要通过命名空间使用 `header`，应将配置改为：

```ts
ns: ["common", "auth", "menu", "header"];
```

完成初始化后，入口文件需要导入该模块一次，使初始化代码执行。

### 步骤 5：在应用入口初始化国际化

本项目在 `src/main.tsx` 中使用副作用导入：

```ts
import "@/features/lang";
```

它位于 `createRoot(...).render(...)` 之前，确保组件渲染前 i18next 已注册资源和 React 插件。入口文件的关键结构如下：

```tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import "@/features/lang";
import App from "./App";
import "./index.css";

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <App />
  </StrictMode>,
);
```

本项目使用全局 i18next 单例和 `initReactI18next`，组件不需要额外包裹 `I18nextProvider`。如果采用多个 i18next 实例，则必须显式使用 `I18nextProvider`，不能混用两种模式。

### 步骤 6：接入 Redux 持久化状态

本项目的 `src/store/modules/app.ts` 在应用状态中保存语言：

```ts
interface AppState {
  language: string | null;
  // 其他应用设置...
}

const initialState: AppState = {
  language: null,
};

const appPersistConfig = {
  key: "shadmin-app",
  storage,
  version: 1,
};
```

`appPersistedReducer` 通过 `redux-persist` 使用 localStorage 保存，因此语言会和主题、布局等应用设置一起恢复。语言 reducer 和 selector 需要提供：

```ts
setLanguage(state, action: PayloadAction<string | null>) {
  state.language = action.payload
}

selectLanguage: app => app.language
```

应用必须已经使用 `PersistGate`，否则首屏可能在 Redux 尚未恢复时使用默认状态。当前项目的 `StoreProvider` 结构为：

```tsx
<ReduxProvider store={store}>
  <PersistGate
    loading={<FullScreenLoader open text="Loading..." />}
    persistor={persistor}
  >
    {children}
  </PersistGate>
</ReduxProvider>
```

这里形成了两个语言持久化来源：i18next detector 默认使用的 localStorage，以及 Redux Persist 的 `shadmin-app`。因此切换语言时必须同时更新 i18next 和 Redux，不能只更新其中一个。

### 步骤 7：创建语言同步 Provider

创建 `src/features/lang/LanguageProvider.tsx`：

```tsx
import { useCallback, useEffect } from "react";
import { useAppDispatch, useAppSelector } from "@/store/hooks";
import { appActions, appSelectors } from "@/store/modules/app";
import i18n from "./index";

export function LanguageProvider({ children }: { children: React.ReactNode }) {
  const dispatch = useAppDispatch();
  const language = useAppSelector(appSelectors.selectLanguage);

  const setLanguage = useCallback(
    (lang: string) => {
      dispatch(appActions.setLanguage(lang));
    },
    [dispatch],
  );

  useEffect(() => {
    if (language && i18n.language !== language) {
      void i18n.changeLanguage(language);
    }
  }, [language]);

  return <>{children}</>;
}
```

它的作用是：Redux 恢复出语言后，如果与 i18next 当前语言不同，就以 Redux 状态为准切换 i18next。

在 `src/App.tsx` 中，将它放在需要翻译的路由和布局外层：

```tsx
<ThemeProvider>
  <LanguageProvider>
    <WatermarkProvider>
      <Outlet />
    </WatermarkProvider>
  </LanguageProvider>
</ThemeProvider>
```

本项目没有使用 `I18nextProvider`，因为所有组件共享 `src/features/lang/index.ts` 导出的 i18next 单例。`LanguageProvider` 只是同步状态，不是 i18next 的 React Provider。

当前实现中监听 i18next `languageChanged` 事件的代码被注释了，因此外部直接调用 `i18n.changeLanguage()` 时不会自动回写 Redux。新增其他语言切换入口时，应统一调用语言切换函数，或补上事件监听：

```tsx
useEffect(() => {
  const handleLanguageChanged = (lang: string) => {
    if (lang !== language) {
      setLanguage(lang);
    }
  };

  i18n.on("languageChanged", handleLanguageChanged);
  return () => i18n.off("languageChanged", handleLanguageChanged);
}, [language, setLanguage]);
```

### 步骤 8：实现语言选择器

本项目的 `src/features/lang/LanguageDropMenu.tsx` 使用 `LANGUAGE_RECORDS` 渲染选项，并按以下顺序切换：

```tsx
const currentLanguage =
  useAppSelector(appSelectors.selectLanguage) ||
  i18n.language ||
  DEFAULT_LANGUAGE;

const handleValueChange = (value: string) => {
  i18n.changeLanguage(value).then(() => {
    dispatch(appActions.setLanguage(value));
  });
};
```

先等待 `i18n.changeLanguage` 完成，再写 Redux，是为了避免语言检测器的 localStorage 写入和 Redux 持久化之间产生竞态。界面文案使用默认 `common` 命名空间：

```tsx
const { t } = useTranslation()

<DropdownMenuLabel>{t('changeLanguage')}</DropdownMenuLabel>
```

语言选择器应满足：

1. 当前选项来自 Redux、i18next 或默认语言的兜底值。
2. 可选项只来自已存在资源的语言。
3. 切换后确认页面、菜单、面包屑和标签页同步刷新。
4. 刷新浏览器后仍保持选择的语言。

### 步骤 9：在 React 组件中使用翻译

组件中通过 `useTranslation` 获取 `t`：

```tsx
import { useTranslation } from "react-i18next";

export function LoginButton() {
  const { t } = useTranslation();

  return <button>{t("auth:common.login")}</button>;
}
```

默认命名空间 `common` 的 key 可以省略 namespace：

```tsx
const { t } = useTranslation()

<span>{t('confirm')}</span>
<span>{t('file.selectedFiles', { count: 3 })}</span>
```

其他命名空间显式写出：

```tsx
const { t } = useTranslation()

<h1>{t('menu:dashboard.title')}</h1>
<p>{t('auth:login.loginWithUsernameDescription')}</p>
```

本项目将翻译应用在以下位置：

- 登录、注册页的标题、占位符、错误提示和按钮。
- 菜单、顶部导航、Logo、面包屑和路由标签页。
- 表格列标题、筛选项、上传/下载提示、Toast 和弹窗。
- 设置面板、主题选项、全屏按钮和用户菜单。
- 日期选择器、图表标题及图表日期格式。

禁止在新业务 UI 中直接写面向用户的固定中文或英文。新增文案时先在各语言资源中增加 key，再在组件中调用 `t`。

### 步骤 10：让菜单、路由和面包屑支持语言切换

#### 菜单

本项目的 `src/hooks/useMenu.ts` 使用 `useTranslation`，并在 `useMemo` 中构造菜单：

```tsx
const { t } = useTranslation();

const menuData = useMemo(
  () => [
    {
      name: "dashboard",
      path: "#",
      meta: { title: t("menu:dashboard.title") },
    },
  ],
  [t],
);
```

把 `t` 放入依赖数组，语言变化后才能重新生成菜单标题。

#### 路由元数据

动态路由中使用翻译 key 保存标题：

```ts
{
  path: 'basicTable',
  handle: { title: 'menu:table.basicTable' },
}
```

`src/layout/components/Breadcrumb.tsx` 在渲染时调用 `t(String(item.title))`，因此路由 handle 保存 key 而不是已经翻译的文本，可以在切换语言后重新显示。

当前路由配置仍有部分标题直接写成中文，例如静态路由的 `登录页面`、动态路由的 `仪表盘` 和 `数据可视化`。这种写法只能保留固定中文，英文环境下不会自动翻译。要实现完整国际化，应将它们改成资源 key，例如：

```ts
handle: {
  title: "menu:dashboard.title";
}
```

并在每种语言的 `menu.json` 中补充对应 key。

#### 标签页

`src/layout/components/routeTabs/index.tsx` 会根据当前菜单重新同步已打开标签的 `title`：

```tsx
const menuItem = getActiveMenuItem(tabItem.path, menuData);

return {
  ...tabItem,
  title: menuItem?.meta?.title ?? tabItem.title,
};
```

这是必要的，因为 Redux 中的标签页状态保存的是已经翻译后的文本，而不是 key。新增路由标签页时，应确保它能够在 `menuData` 中找到对应路径和翻译标题。

初始标签页在 `src/store/modules/tabs.ts` 中通过 `translate('menu:home')` 生成。非 React 模块不能使用 hook，因此需要使用下一节的共享翻译函数。

### 步骤 11：在非 React 模块中使用翻译

创建 `src/features/lang/shared.ts`：

```ts
import type { TOptions } from "i18next";
import i18n from "./index";

export function t(
  key: string,
  options?: TOptions | Record<string, unknown>,
): string {
  return i18n.t(key, options);
}

export function translate(
  key: string,
  options: TOptions & { defaultValue?: string } = {},
): string {
  return i18n.t(key, options);
}

export default t;
```

Redux slice 初始值、路由工具、API 错误处理等非 React 代码可以调用：

```ts
import { translate } from "@/features/lang/shared";

const initialTabsData = [
  { title: translate("menu:home"), path: "/home/index", active: true },
];
```

注意：非 React 代码直接调用 `i18n.t` 不会像 `useTranslation` 一样自动触发 React 重渲染。需要随语言变化更新的内容，应放在组件中通过 hook 计算，或在语言变化后显式重建状态。

### 步骤 12：让表格列和回调文案响应语言

表格列定义通常不是组件 JSX，而是接收 `TFunction`：

```tsx
import type { TFunction } from "i18next";

export function createColumns(t: TFunction) {
  return [
    {
      id: "username",
      header: t("table.username"),
    },
    {
      id: "actions",
      header: t("table.actions"),
    },
  ];
}
```

页面中通过 `useTranslation` 获取 `t` 后创建列。不要在模块加载阶段固定调用一次翻译，否则切换语言后列标题可能保持旧语言。需要把列定义放入组件的 `useMemo`，并以 `t` 为依赖，或在每次渲染时重新生成。

### 步骤 13：处理表单校验和动态错误消息

本项目在登录页和用户编辑表单中，将翻译后的文案传给 Zod：

```tsx
const loginFormSchema = useMemo(
  () =>
    z.object({
      username: z.string().min(1, t("auth:common.usernameNotEmpty")),
      password: z
        .string()
        .min(6, t("auth:common.passwordMinLength", { count: 6 }))
        .max(20, t("auth:common.passwordMaxLength", { count: 20 })),
    }),
  [t],
);
```

必须根据 `t` 或 `i18n.language` 重新创建 schema。登录页还监听语言变化并触发 `form.trigger()`，使已经显示的 Zod 错误消息更新为新语言：

```tsx
useEffect(() => {
  if (form.formState.isDirty) {
    void form.trigger();
  }
}, [i18n.language, form]);
```

同理，Toast、Dialog、上传错误和 API 错误也应在显示时调用当前语言的 `t`，不要在模块初始化时缓存翻译字符串。

### 步骤 14：同步日期和浏览器格式化区域

翻译文本和日期格式是两个不同问题。本项目分别处理：

1. `DatePicker` 和 `DatetimeSelect` 根据 Redux 语言选择 `date-fns` 或 `react-day-picker` locale。
2. 图表使用 `i18n.language` 映射到 `zh-CN` 或 `en-US`，调用 `toLocaleDateString`。

日期选择器使用类似映射：

```tsx
import { enUS, zhCN } from "date-fns/locale";

const localeMap = {
  zh: zhCN,
  en: enUS,
};

const currentLanguage = useAppSelector(
  (state) => state.app.language as "zh" | "en" | undefined,
);
const calendarLocale = currentLanguage === "en" ? localeMap.en : localeMap.zh;
```

图表使用类似映射：

```ts
const languageMap = {
  zh: "zh-CN",
  en: "en-US",
};

new Date(value).toLocaleDateString(languageMap[i18n.language] || "en-US", {
  month: "short",
  day: "numeric",
});
```

新增语言时必须同时扩展这些映射，否则界面文字可能已经切换，但日期仍使用错误的区域格式。当前日期组件把 Redux 中没有语言时默认处理为中文，而 i18next 默认语言是英文；首屏需要严格一致时，应统一使用 `i18n.language` 或在语言恢复完成后再渲染日期组件。

## 五、项目中需要特别注意的现状

### 1. 支持语言列表和资源必须保持一致

当前真正可切换的是 `zh`、`en`。`config.ts` 中预留的语言代码不代表这些语言已经实现。新增语言至少要完成一套 JSON、资源聚合、选择器、日期格式和验证。

### 2. 命名空间声明需要覆盖实际资源

当前 `resources` 包含 `header`，但 `i18next.init` 的 `ns` 只有 `common`、`auth`、`menu`。如果使用 `header:key`，应把 `header` 加入 `ns` 并验证运行时行为。

### 3. 路由标题仍有未国际化文本

动态路由部分使用 `menu:*` key，但静态路由和部分父级路由仍直接写中文。完整国际化时应统一使用 key，并补齐每种语言的资源。

### 4. Redux 和 i18next 有双向同步边界

当前语言选择器会先 `changeLanguage` 再 dispatch，`LanguageProvider` 会在 Redux 恢复后把 Redux 语言同步给 i18next，但 `languageChanged` 监听代码被注释。新增入口应避免直接改变 i18next 后不更新 Redux。

### 5. 翻译 key 缺失时要检查资源一致性

i18next 在缺少 key 时可能显示 key 本身或回退语言。新增或修改文案后，应逐语言检查 key。尤其要检查菜单、路由 handle、表格列、表单 schema 和非 React 初始状态，这些位置不一定在页面 JSX 中直接可见。

## 六、验证和测试步骤

### 1. 静态检查

```bash
pnpm lint
pnpm typecheck
pnpm build
```

确保资源 JSON、TypeScript 导入和组件依赖没有类型或构建错误。

### 2. 语言切换验证

按以下顺序手动验证：

1. 首次打开应用，确认浏览器语言可以影响初始语言。
2. 在语言菜单选择中文，确认页面正文、菜单、Logo、面包屑、标签页、按钮、Toast 和校验错误均切换。
3. 刷新页面，确认语言保持不变。
4. 选择英文并刷新，确认不会被 Redux Persist 或浏览器检测器覆盖回中文。
5. 在登录页输入非法值，切换语言，确认已显示的表单错误消息更新。
6. 打开表格、图表、日期选择器，确认列标题、图表标签、日期月份和日期格式同步变化。
7. 关闭并重新打开已有路由标签，确认标签标题使用当前语言。
8. 检查静态异常页、登录页和不存在路由，确认没有遗留固定中文。

### 3. 资源一致性检查

可以编写一个脚本，以英文资源作为基准递归比较中文资源 key。至少检查：

- 两种语言是否拥有同样的命名空间文件。
- 嵌套对象路径是否一致。
- 插值变量是否一致，例如英文使用 `{{count}}` 时中文也必须使用 `{{count}}`。
- 代码中引用的 namespace 和 key 是否真实存在。

当前项目没有配置自动化翻译 key 检查，因此这项工作需要人工完成或另行增加脚本。

### 4. 缺失翻译排查

在浏览器中看到 `menu:xxx`、`table.xxx` 或其他 key 时，按以下顺序排查：

1. 检查调用时的 namespace 是否正确，例如 `menu:home` 与 `home` 不是同一个 key。
2. 检查当前语言目录是否存在对应 JSON。
3. 检查语言的 `index.ts` 是否导入并导出该命名空间。
4. 检查 `locales/index.ts` 是否聚合该语言。
5. 检查 `i18n.init` 的 `ns` 是否包含该命名空间。
6. 检查 JSON 的嵌套路径、大小写和拼写。
7. 检查是否实际使用了静态中文而不是翻译函数。

## 七、新增一条国际化文案的标准流程

以新增“导出成功”为例：

1. 在 `src/features/lang/locales/en/common.json` 增加：

   ```json
   { "exportSuccess": "Export successful" }
   ```

2. 在 `src/features/lang/locales/zh/common.json` 增加：

   ```json
   { "exportSuccess": "导出成功" }
   ```

3. 在组件中导入 `useTranslation`：

   ```tsx
   const { t } = useTranslation();
   toast.success(t("exportSuccess"));
   ```

4. 如果文案来自菜单、登录或顶部区域，放入对应 namespace，并使用完整 key，例如 `t('menu:exportSuccess')`。
5. 如果文案用于 Zod schema、表格列或 Redux 初始值，确保它会在语言变化后重新计算，或使用共享 `translate` 函数并在切换时同步更新。
6. 运行 lint、类型检查和构建。
7. 逐个切换语言，检查文案、插值和布局是否正常。

`.vscode/settings.json` 中可以配置 i18n Ally，以匹配本项目的资源组织方式：

```jsonc
{
  "i18n-ally.displayLanguage": "zh",
  "i18n-ally.enabledParsers": ["ts", "json"],
  "i18n-ally.enabledFrameworks": ["react-i18next"],
  "i18n-ally.pathMatcher": "{locale}/{namespace}.json",
  "i18n-ally.localesPaths": ["src/features/lang/locales"],
  "i18n-ally.sourceLanguage": "en",
}
```

本项目还启用了命名空间、嵌套 key 和 `react-i18next` 解析支持，开发者可以通过 i18n Ally 查看 key 引用、快速定位资源和辅助翻译。但编辑器插件只是开发辅助，最终仍需通过运行时切换和构建检查验证国际化功能。
