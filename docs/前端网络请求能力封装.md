# 前端网络请求能力封装

本文面向一个全新的 React + TypeScript 项目，提供一套可以直接实施的网络请求封装方案。方案使用 Axios 负责 HTTP 通信，使用 TanStack Query 负责查询缓存、请求状态、重试和数据刷新。

完成全部步骤后，项目将具备：

- 统一 Axios 实例和环境配置；
- 自动注入登录 Token；
- 统一处理 HTTP 错误和业务错误；
- 支持请求超时、取消和重复请求控制；
- 使用 TanStack Query 管理查询缓存和 mutation 状态；
- 按业务域拆分 URL、类型、API 函数和 React Hooks；
- 支持分页、筛选、上传、下载和手动触发请求；
- 支持 mutation 后自动刷新相关查询；
- 统一处理 loading、error、empty 和成功反馈；
- 通过 TypeScript 保证请求参数和响应数据类型正确。

## 一、先确定分层方案

网络请求功能分为四层：

```text
页面组件
  ↓ 调用业务 Hook
React Query Hooks
  ↓ 提供 queryKey、queryFn、mutationFn
API Modules
  ↓ 提供 URL、HTTP 方法、参数和响应类型
Axios Request Client
  ↓ 处理 baseURL、Token、错误、取消、响应转换
后端服务
```

每一层只负责自己的事情：

| 层级             | 负责内容                                       | 不负责内容                 |
| ---------------- | ---------------------------------------------- | -------------------------- |
| 页面组件         | 组装参数、展示状态、用户反馈                   | 直接调用 Axios、拼接 URL   |
| React Query Hook | 缓存、请求状态、重试、失效和 mutation 生命周期 | 拼接业务提示文案、操作 DOM |
| API Module       | 一个接口的 URL、方法、请求和响应类型           | React Hook、Toast、缓存    |
| Axios Client     | HTTP 发送、Token、业务错误转换、取消           | 页面缓存和组件渲染         |

查询的标准调用链：

```text
页面 params
    ↓
useProductList(params)
    ↓
queryKey = ['product', 'list', params]
queryFn = productListApi(params, signal)
    ↓
request.post('/product/list', params, { signal })
    ↓
Axios 拦截器
    ↓
后端响应
    ↓
转换为业务响应或 ApiError
    ↓
TanStack Query 更新缓存和页面状态
```

变更的标准调用链：

```text
用户操作
    ↓
mutation.mutate(params)
    ↓
API Module
    ↓
Axios Request Client
    ↓
成功：invalidateQueries / 更新缓存 / 显示提示
失败：显示错误 / 保留表单状态
结束：关闭弹窗 / 恢复按钮
```

## 五、定义通用类型和错误模型

### 步骤 7：定义统一响应类型

创建 `src/services/api/types/common.ts`：

```ts
import type { AxiosRequestConfig } from "axios";

export interface ResponseData<T = unknown> {
  code: number;
  message?: string;
  data: T;
}

export interface RequestOptions extends AxiosRequestConfig {
  showLoading?: boolean;
  showError?: boolean;
  showSuccess?: boolean;
  cancelDuplicate?: boolean;
  withToken?: boolean;
}

export type RequestConfig<D = unknown> = AxiosRequestConfig<D> & RequestOptions;
```

统一响应假设后端返回：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

如果后端使用 `msg` 而不是 `message`，从一开始就统一成真实字段，不要在不同接口中混用。

### 步骤 8：创建统一错误类型

创建 `src/services/api/error.ts`：

```ts
export type ApiErrorKind =
  | "http"
  | "business"
  | "network"
  | "timeout"
  | "cancel"
  | "unknown";

interface ApiErrorOptions {
  kind: ApiErrorKind;
  message: string;
  status?: number;
  code?: number;
  details?: unknown;
}

export class ApiError extends Error {
  readonly kind: ApiErrorKind;
  readonly status?: number;
  readonly code?: number;
  readonly details?: unknown;

  constructor(options: ApiErrorOptions) {
    super(options.message);
    this.name = "ApiError";
    this.kind = options.kind;
    this.status = options.status;
    this.code = options.code;
    this.details = options.details;
  }
}
```

这样页面不需要猜测错误究竟是 AxiosError、业务对象还是字符串：

```ts
if (error instanceof ApiError) {
  if (error.kind === "business") {
    // 业务错误
  }

  if (error.kind === "network") {
    // 网络错误
  }
}
```

## 六、配置 HTTP 和 Query 默认值

### 步骤 9：创建 `config.ts`

创建 `src/services/api/config.ts`：

```ts
import axios from "axios";

export const HTTP_CONFIG = {
  timeout: 10_000,
  withCredentials: true,
  successStatus: 200,
  unauthorizedStatus: 401,
  successCode: 200,
  unauthorizedCode: 401,
} as const;

const MAX_QUERY_RETRY = 1;

export function shouldRetryQuery(failureCount: number, error: unknown) {
  if (failureCount >= MAX_QUERY_RETRY) {
    return false;
  }

  if (axios.isAxiosError(error)) {
    const status = error.response?.status;

    if (status === undefined || (status >= 500 && status < 600)) {
      return true;
    }
  }

  if (error instanceof Error) {
    return /network|timeout/i.test(error.message);
  }

  return false;
}

export const DEFAULT_QUERY_OPTIONS = {
  gcTime: 10 * 60 * 1000,
  staleTime: 30 * 1000,
  networkMode: "online" as const,
  refetchOnMount: true,
  refetchOnReconnect: true,
  refetchOnWindowFocus: false,
  retry: shouldRetryQuery,
  retryDelay: 2_000,
  retryOnMount: true,
};

export const DEFAULT_MUTATION_OPTIONS = {
  networkMode: "online" as const,
  retry: false,
  retryDelay: 2_000,
};
```

查询和 mutation 的重试策略不要完全相同：

- 查询通常可以对网络错误和 5xx 重试一次；
- 删除、新增、编辑等写操作默认不重试，避免重复提交；
- 明确幂等的 mutation 才考虑开启重试。

## 七、实现 Axios 请求客户端

### 步骤 10：实现重复请求管理

创建 `src/services/api/request/axiosCancel.ts`：

```ts
import type { AxiosRequestConfig } from "axios";

class AxiosCancelManager {
  private pendingMap = new Map<string, AbortController>();

  private generateKey(config: AxiosRequestConfig) {
    return [
      config.method?.toUpperCase() || "GET",
      config.url || "",
      JSON.stringify(config.params ?? {}),
      JSON.stringify(config.data ?? {}),
    ].join("&");
  }

  add(config: AxiosRequestConfig, cancelDuplicate = true) {
    const key = this.generateKey(config);

    if (cancelDuplicate) {
      this.remove(config);
    }

    const controller = new AbortController();
    this.pendingMap.set(key, controller);

    // 如果调用方已经提供 signal，应优先保留调用方 signal。
    // TanStack Query 会通过它取消未使用的查询。
    if (!config.signal) {
      config.signal = controller.signal;
    }
  }

  remove(config: AxiosRequestConfig) {
    const key = this.generateKey(config);
    const controller = this.pendingMap.get(key);

    if (controller) {
      controller.abort();
      this.pendingMap.delete(key);
    }
  }

  complete(config: AxiosRequestConfig) {
    this.pendingMap.delete(this.generateKey(config));
  }

  cancelAll() {
    for (const controller of this.pendingMap.values()) {
      controller.abort();
    }

    this.pendingMap.clear();
  }

  isCancel(error: unknown) {
    if (!error || typeof error !== "object") {
      return false;
    }

    const value = error as { code?: string; name?: string };
    return value.code === "ERR_CANCELED" || value.name === "AbortError";
  }
}

export const axiosCancel = new AxiosCancelManager();
```

该管理器完成：

- 为请求生成唯一 key；
- 相同请求发起时取消旧请求；
- 请求结束后清理 Map；
- 路由切换或退出登录时取消全部请求；
- 识别 Axios 的取消错误。

Query 的 `signal` 需要传入 Axios，否则 TanStack Query 取消查询时，底层 HTTP 请求仍可能继续执行。上面的实现优先保留外部 `signal`，因此带有 TanStack Query `signal` 的请求由 Query 负责取消；不带外部 `signal` 的普通请求由重复请求管理器负责取消。如果需要两者同时生效，可以进一步使用 `AbortSignal.any([externalSignal, internalSignal])` 合并两个信号。

### 步骤 11：创建 Axios 实例

创建 `src/services/api/request/index.ts`：

```ts
import axios, {
  type AxiosError,
  type AxiosInstance,
  type AxiosResponse,
} from "axios";
import { ApiError } from "../error";
import { HTTP_CONFIG } from "../config";
import type {
  RequestConfig,
  RequestOptions,
  ResponseData,
} from "../types/common";
import { axiosCancel } from "./axiosCancel";

const instanceConfig = {
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: HTTP_CONFIG.timeout,
  withCredentials: HTTP_CONFIG.withCredentials,
};

class RequestClient {
  private readonly instance: AxiosInstance;

  constructor() {
    this.instance = axios.create(instanceConfig);
    this.setupInterceptors();
  }

  private setupInterceptors() {
    this.instance.interceptors.request.use(
      (config: RequestConfig) => {
        const options = {
          showLoading: false,
          showError: false,
          showSuccess: false,
          cancelDuplicate: true,
          withToken: true,
          ...config,
        };

        Object.assign(config, options);

        if (options.cancelDuplicate) {
          axiosCancel.add(config, true);
        }

        if (options.withToken) {
          const token = localStorage.getItem("accessToken");

          if (token) {
            config.headers.set("Authorization", `Bearer ${token}`);
          }
        }

        return config;
      },
      (error) => Promise.reject(error),
    );

    this.instance.interceptors.response.use(
      (response) => this.handleResponse(response),
      (error) => this.handleError(error),
    );
  }

  private handleResponse(response: AxiosResponse) {
    const config = response.config as RequestConfig;
    axiosCancel.complete(config);

    // 文件下载不一定有 code/message/data 包装。
    if (
      config.responseType === "blob" ||
      config.responseType === "arraybuffer"
    ) {
      return response.data;
    }

    const body = response.data as ResponseData;

    if (body?.code === HTTP_CONFIG.unauthorizedCode) {
      this.handleUnauthorized();
      throw new ApiError({
        kind: "business",
        code: body.code,
        status: response.status,
        message: body.message || "登录状态已失效",
        details: body,
      });
    }

    if (body?.code !== HTTP_CONFIG.successCode) {
      throw new ApiError({
        kind: "business",
        code: body?.code,
        status: response.status,
        message: body?.message || "请求失败",
        details: body,
      });
    }

    return body;
  }

  private async handleError(error: AxiosError) {
    const config = error.config as RequestConfig | undefined;

    if (config) {
      axiosCancel.complete(config);
    }

    if (axiosCancel.isCancel(error)) {
      return Promise.reject(
        new ApiError({
          kind: "cancel",
          message: "请求已取消",
          details: error,
        }),
      );
    }

    if (error.response?.status === HTTP_CONFIG.unauthorizedStatus) {
      this.handleUnauthorized();
    }

    if (error.code === "ECONNABORTED" || error.message.includes("timeout")) {
      return Promise.reject(
        new ApiError({
          kind: "timeout",
          status: error.response?.status,
          message: "请求超时，请稍后重试",
          details: error,
        }),
      );
    }

    if (!error.response) {
      return Promise.reject(
        new ApiError({
          kind: "network",
          message: "网络连接失败，请检查网络",
          details: error,
        }),
      );
    }

    return Promise.reject(
      new ApiError({
        kind: "http",
        status: error.response.status,
        message: "服务器请求失败",
        details: error,
      }),
    );
  }

  private handleUnauthorized() {
    // 只清理认证数据，避免删除主题、语言等其他应用设置。
    localStorage.removeItem("accessToken");
    localStorage.removeItem("userInfo");

    if (window.location.pathname !== "/login") {
      window.location.href = "/login";
    }
  }

  request<T = unknown, D = unknown>(config: RequestConfig<D>) {
    return this.instance.request<T, T>(config);
  }

  get<T = unknown, P = unknown>(
    url: string,
    params?: P,
    config?: Omit<RequestOptions, "method" | "url" | "params">,
  ) {
    return this.request<T, P>({
      ...config,
      method: "GET",
      url,
      params,
    });
  }

  post<T = unknown, D = unknown>(
    url: string,
    data?: D,
    config?: Omit<RequestOptions, "method" | "url" | "data">,
  ) {
    return this.request<T, D>({
      ...config,
      method: "POST",
      url,
      data,
    });
  }

  put<T = unknown, D = unknown>(
    url: string,
    data?: D,
    config?: RequestOptions,
  ) {
    return this.request<T, D>({
      ...config,
      method: "PUT",
      url,
      data,
    });
  }

  delete<T = unknown, P = unknown>(
    url: string,
    params?: P,
    config?: RequestOptions,
  ) {
    return this.request<T, P>({
      ...config,
      method: "DELETE",
      url,
      params,
    });
  }

  cancelAll() {
    axiosCancel.cancelAll();
  }
}

export const request = new RequestClient();
export default request;
```

### 步骤 12：检查 Axios 返回值设计

上面的实现约定：

- 普通 JSON 接口返回 `ResponseData<T>`；
- 业务 code 不成功时抛出 `ApiError`；
- HTTP 401 清理认证并跳转；
- Blob 和 ArrayBuffer 直接返回二进制数据；
- 网络、超时、取消和 HTTP 错误统一转换为 `ApiError`。

API Module 因此可以直接声明：

```ts
request.post<ResponseData<ProductList>>(url, params);
```

页面只需要处理 `data.data`，不再重复解析 Axios response。

## 八、创建 QueryClient

### 步骤 13：创建全局 QueryClient

创建 `src/services/api/queryClient.ts`：

```ts
import { MutationCache, QueryCache, QueryClient } from "@tanstack/react-query";
import { DEFAULT_MUTATION_OPTIONS, DEFAULT_QUERY_OPTIONS } from "./config";

export const queryClient = new QueryClient({
  defaultOptions: {
    queries: DEFAULT_QUERY_OPTIONS,
    mutations: DEFAULT_MUTATION_OPTIONS,
  },
  queryCache: new QueryCache({
    onError: (error) => {
      if (import.meta.env.DEV) {
        console.error("Query error:", error);
      }
    },
  }),
  mutationCache: new MutationCache({
    onError: (error) => {
      if (import.meta.env.DEV) {
        console.error("Mutation error:", error);
      }
    },
  }),
});
```

不要在每个页面中 `new QueryClient()`。整个浏览器应用应共享一个 QueryClient，否则不同页面之间无法共享缓存。

### 步骤 14：挂载 QueryClientProvider

### 步骤 17：创建 API Module

创建 `src/services/api/modules/product.ts`：

```ts
import request from "../request";
import type { RequestOptions } from "../types/common";
import type {
  DeleteProductParams,
  DeleteProductResponse,
  ProductListParams,
  ProductListResponse,
} from "../types/product";
import { PRODUCT_URLS } from "../urls/product";

export function productListApi(
  params: ProductListParams,
  options?: RequestOptions,
) {
  return request.post<ProductListResponse>(PRODUCT_URLS.LIST, params, options);
}

export function deleteProductApi(
  params: DeleteProductParams,
  options?: RequestOptions,
) {
  return request.post<DeleteProductResponse>(
    PRODUCT_URLS.DELETE,
    params,
    options,
  );
}
```

API Module 的规则：

- 只能负责接口调用；
- 不调用 React Hook；
- 不显示 Toast；
- 不直接操作 QueryClient；
- 接收可选的 Axios 配置，尤其是 `signal`；
- 返回明确的 Promise 类型。

## 十、创建 Query Key

### 步骤 18：建立 Query Key 工厂

创建 `src/services/api/keys/index.ts`：

```ts
import type { ProductListParams } from "../types/product";

export const queryKeys = {
  product: {
    all: ["product"] as const,
    lists: () => [...queryKeys.product.all, "list"] as const,
    list: (params: ProductListParams) =>
      [...queryKeys.product.lists(), params] as const,
    details: () => [...queryKeys.product.all, "detail"] as const,
    detail: (id: string) => [...queryKeys.product.details(), id] as const,
  },
} as const;
```

推荐使用分层 key：

```text
product
├── list
│   └── params
└── detail
    └── id
```

这样可以精确失效：

```ts
queryClient.invalidateQueries({
  queryKey: queryKeys.product.lists(),
});
```

也可以只失效某个参数的列表：

```ts
queryClient.invalidateQueries({
  queryKey: queryKeys.product.list(params),
});
```

凡是会影响返回数据的参数，都必须进入 queryKey，包括分页、搜索、筛选、排序和用户身份范围。

## 十一、封装业务 Hooks

### 步骤 19：创建列表查询 Hook

创建 `src/services/api/hooks/useProduct.ts`：

```ts
import {
  keepPreviousData,
  useMutation,
  useQuery,
  useQueryClient,
} from "@tanstack/react-query";
import { deleteProductApi, productListApi } from "../modules/product";
import { queryKeys } from "../keys";
import type { DeleteProductParams, ProductListParams } from "../types/product";

export function useProductList(params: ProductListParams) {
  return useQuery({
    queryKey: queryKeys.product.list(params),
    queryFn: ({ signal }) => productListApi(params, { signal }),
    placeholderData: keepPreviousData,
  });
}
```

将 Query 提供的 `signal` 传给 Axios，可以在组件卸载、query key 变化或查询被取消时真正中止网络请求。

### 步骤 20：创建删除 mutation

```ts
export function useDeleteProduct() {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: (params: DeleteProductParams) => deleteProductApi(params),
    onSuccess: async () => {
      await queryClient.invalidateQueries({
        queryKey: queryKeys.product.lists(),
      });
    },
  });
}
```

将列表刷新放在 Hook 中，可以让所有使用该 mutation 的页面拥有一致行为。如果不同页面刷新策略不同，也可以把 `onSuccess` 留给页面，通过 mutation options 覆盖。

### 步骤 21：按接口类型选择 Query 或 Mutation

使用 `useQuery`：

- 页面进入时自动获取列表；
- 获取详情；
- 查询字典、部门树和下拉选项；
- 需要缓存和重新获取的数据。

使用 `useMutation`：

- 登录；
- 新增、编辑、删除；
- 上传文件；
- 导出文件；
- 点击按钮后才执行的非查询操作。

不要为了“点击后请求”把所有接口都做成 `enabled: false` 的 query。没有缓存需求的动作使用 mutation 更清晰。

## 十二、在页面中使用

### 步骤 22：实现列表页面

```tsx
import { useMemo, useState } from "react";
import { useProductList } from "@/services/api/hooks/useProduct";

export function ProductPage() {
  const [page, setPage] = useState(1);
  const [keyword, setKeyword] = useState("");

  const params = useMemo(
    () => ({
      page,
      pageSize: 20,
      keyword: keyword || undefined,
    }),
    [keyword, page],
  );

  const {
    data: response,
    isLoading,
    isFetching,
    isError,
    error,
    refetch,
  } = useProductList(params);

  if (isLoading) {
    return <div>首次加载中...</div>;
  }

  if (isError) {
    return (
      <div>
        <p>{error instanceof Error ? error.message : "加载失败"}</p>
        <button type="button" onClick={() => void refetch()}>
          重试
        </button>
      </div>
    );
  }

  const products = response?.data?.list ?? [];

  return (
    <section>
      {isFetching && <div>正在更新...</div>}
      {products.length === 0 && <div>暂无数据</div>}
      {products.map((product) => (
        <div key={product.id}>
          {product.name}：{product.price}
        </div>
      ))}
      <button type="button" onClick={() => setPage(page + 1)}>
        下一页
      </button>
    </section>
  );
}
```

### 步骤 23：区分加载状态

页面应区分以下状态：

- `isLoading`：第一次请求且没有旧数据；
- `isFetching`：任何请求进行中，包括分页切换和后台刷新；
- `isPending`：mutation 执行中；
- `isError`：查询失败；
- `data` 为空：接口成功但没有数据。

列表分页时配合 `keepPreviousData`，可以在新页面请求期间继续显示旧列表，只显示一个刷新提示。

### 步骤 24：实现删除操作

```tsx
import { useDeleteProduct } from "@/services/api/hooks/useProduct";

export function DeleteProductButton({ id }: { id: string }) {
  const deleteMutation = useDeleteProduct();

  return (
    <button
      type="button"
      disabled={deleteMutation.isPending}
      onClick={() => {
        deleteMutation.mutate(
          { id },
          {
            onSuccess: () => {
              window.alert("删除成功");
            },
            onError: (error) => {
              window.alert(error instanceof Error ? error.message : "删除失败");
            },
          },
        );
      }}
    >
      {deleteMutation.isPending ? "删除中..." : "删除"}
    </button>
  );
}
```

mutation Hook 负责失效列表缓存，页面负责按钮禁用和反馈文案。

### 步骤 25：实现文件上传

定义类型：


API Module：

```ts
export function uploadImageApi(file: File, options?: RequestOptions) {
  const formData = new FormData();
```

```ts
export function exportProductApi(options?: RequestOptions) {

    {},
    {
      ...options,
      responseType: "blob",
    },

}
```

Hook：

```ts
export function useExportProduct() {
  return useMutation({
    mutationFn: () => exportProductApi(),

```

```tsx
const exportMutation = useExportProduct();

  exportMutation.mutate(undefined, {
```

### 步骤 28：处理认证过期

收到 HTTP 401 或业务 code 401 时：

1. 清理认证相关存储；
2. 取消不再需要的请求；
3. 跳转到登录页；
4. 避免重复跳转和重复 Toast。


因为这会同时删除主题、语言、用户偏好等无关设置。应精确删除认证 key，或者清理认证对应的 Redux Persist 分区。

## 十五、取消请求和生命周期

### 步骤 29：让 Query 传递 AbortSignal

TanStack Query 的 queryFn 会收到上下文：

```ts
queryFn: ({ signal }) => productListApi(params, { signal });
```

API Module 将 `signal` 继续传给 request：

```ts
productListApi(params, { signal });
```

Request Client 最终将它传给 Axios。这样在以下场景可以中止请求：

- 组件卸载；
- query key 变化；
- 手动取消 Query；
- 页面离开；
- 用户主动取消。

### 步骤 30：取消全部请求

退出登录或切换租户时，可以取消所有待处理请求：

```ts
import request from "@/services/api/request";

function logout() {
  request.cancelAll();
  localStorage.removeItem("accessToken");
}
```

如果同时使用 QueryClient，也可以清除 Query 缓存：

```ts
queryClient.cancelQueries();
queryClient.clear();
```

二者作用不同：

- `request.cancelAll()` 取消 Axios 层的请求；
- `queryClient.cancelQueries()` 取消 Query 层的查询；
- `queryClient.clear()` 清空 Query 缓存。

退出登录时是否清除所有缓存，取决于缓存数据是否与用户身份绑定。多用户切换场景通常应清理。

## 十六、缓存刷新策略

### 步骤 31：mutation 后失效列表

新增、编辑、删除成功后，推荐失效相关列表：

```ts
await queryClient.invalidateQueries({
  queryKey: queryKeys.product.lists(),
});
```

`invalidateQueries` 会将匹配的查询标记为过期，并根据当前组件是否活跃决定是否立即重新获取。

### 步骤 32：更新详情缓存

如果 mutation 返回了更新后的实体，可以直接写入详情缓存：

```ts
queryClient.setQueryData(queryKeys.product.detail(product.id), response);
```

如果列表中也需要立即更新，可以选择：

- 只失效列表，重新请求；
- 通过 `setQueryData` 修改列表缓存；
- 采用乐观更新并在失败时回滚。

在数据一致性优先的管理后台中，先使用失效并重新请求，逻辑更容易验证。

### 步骤 33：避免无意义的手动 refetch

以下写法可以使用，但维护成本较高：

```tsx
onSettled: () => {
  void refetch();
};
```

当多个页面共享同一个列表时，优先使用 QueryClient 的 key 失效：

```ts
onSuccess: () => {
  void queryClient.invalidateQueries({
    queryKey: queryKeys.product.lists(),
  });
};
```

## 十七、统一 loading 和错误提示

### 步骤 34：页面级处理

页面应根据错误类型显示可理解的反馈：

```tsx
function getErrorMessage(error: unknown) {
  if (error instanceof ApiError) {
    if (error.kind === "network") {
      return "网络连接失败，请检查网络";
    }

    if (error.kind === "timeout") {
      return "请求超时，请稍后重试";
    }

    if (error.kind === "business") {
      return error.message;
    }
  }

  return "请求失败，请稍后重试";
}
```

取消错误通常不应该显示普通失败 Toast：

```tsx
onError: (error) => {
  if (error instanceof ApiError && error.kind === "cancel") {
    return;
  }

  toast.error(getErrorMessage(error));
};
```

### 步骤 35：全局处理和局部处理的边界

全局 `QueryCache` 和 `MutationCache` 适合：

- 开发日志；
- 监控上报；
- 全局网络断开提示；
- 统一认证失效。

页面或业务 Hook 适合：

- 删除成功；
- 表单校验失败；
- 导入失败；
- 特定业务的错误说明；
- 成功后的弹窗关闭和列表刷新。

不要在全局回调中对所有错误都弹 Toast，否则页面已经处理过的错误可能重复提示。

## 二十、常见问题排查

### 1. 请求发到了错误地址

检查：

1. `.env` 中是否使用 `VITE_API_BASE_URL`；
2. 修改环境变量后是否重启 Vite；
3. URL 是否已经包含 `/api`，baseURL 是否又重复包含；
4. 浏览器 Network 面板中的 Request URL；
5. 开发代理配置是否覆盖了 baseURL。

### 2. 页面显示业务错误但 `isError` 为 false

检查 Axios response interceptor 是否真的 `throw` 或 `Promise.reject` 业务错误。如果只返回了错误响应对象，TanStack Query 会把它当作成功数据。

### 3. queryKey 变化但没有重新请求

检查：

- 参数是否真的进入 queryKey；
- 参数对象是否被错误地固定；
- Query 是否设置了 `enabled: false`；
- 数据是否仍处于 `staleTime` 内；
- 是否误用了相同的静态 key。

### 4. 请求取消了但浏览器请求仍在继续

确认：

- queryFn 是否使用了 `{ signal }`；
- API Module 是否接收并传递 signal；
- Request Client 是否把 signal 传给 Axios；
- 重复请求管理器是否覆盖了调用方传入的 signal。

### 5. 删除成功但列表不更新

在 mutation 成功后调用：

```ts
await queryClient.invalidateQueries({
  queryKey: queryKeys.product.lists(),
});
```

并确认列表使用的 key 与失效 key 的前缀一致。

### 6. 上传接口返回 415

通常是手动设置了错误的 `Content-Type`。删除 `application/json`，让浏览器根据 FormData 自动设置 multipart boundary。

### 7. 下载文件内容损坏

检查：

- Axios 是否设置 `responseType: 'blob'`；
- response interceptor 是否直接返回 Blob；
- 是否错误地执行了 `JSON.stringify(blob)`；
- 是否在 `URL.revokeObjectURL` 前完成了点击；
- 文件扩展名和后端返回类型是否一致。

### 8. 401 后所有设置都丢失

不要使用 `localStorage.clear()`。只删除 Token、用户信息和认证相关的 persist key。

## 二十二、总结

这套封装的核心边界是：

```text
Axios：负责 HTTP 传输和拦截
API Module：负责接口定义
TanStack Query：负责服务端状态和缓存
页面：负责业务交互和视觉反馈
```

新增接口时遵循以下顺序：

```text
类型
  → URL
  → API Module
  → Query Key
  → Query Hook / Mutation Hook
  → 页面状态和反馈
```

只要保持这个顺序，就可以避免在页面中散落 Axios 调用、重复实现 loading 和错误处理，也能让分页、筛选、缓存失效、请求取消和认证处理拥有统一行为。
