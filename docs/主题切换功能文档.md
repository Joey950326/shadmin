# 主题切换功能文档

本文基于项目现有代码，整理主题切换功能的实现方案、文件职责、运行流程、状态变化和落地步骤，便于后续维护、扩展主题色或排查主题显示问题。

## 一、功能范围和整体方案

项目中的“主题”并不只有亮色/暗色切换，还包含四类可配置项：

1. **主题模式**：亮色 `light`、暗色 `dark`、跟随系统 `system`。
2. **主题色**：通过 CSS 变量切换一组预设配色。
3. **灰色模式**：给页面根节点增加 `grayscale(100%)` 滤镜。
4. **色弱模式**：给页面根节点增加 `invert(80%)` 滤镜。

整体采用“Redux 保存配置、ThemeProvider 执行副作用、CSS 变量负责视觉表现”的方案：

```text
用户操作主题控件
        ↓
Redux app 状态更新
        ↓
ThemeProvider 订阅状态
        ↓
根据配置修改 document.documentElement
        ↓
.dark / .theme-* 类名和 CSS 变量生效
        ↓
Tailwind 工具类、组件和图表更新颜色
```

核心原则是：

- Redux 保存用户选择，使用 `redux-persist` 持久化到 localStorage；
- React 组件不直接到处操作 DOM，统一由 `ThemeProvider` 和 `shared.ts` 执行；
- 暗色模式通过根节点的 `dark` 类名控制；
- 主题色通过根节点的 `theme-{color}` 类名控制；
- 组件使用 `bg-background`、`text-foreground`、`bg-primary` 等语义化颜色，不直接绑定具体颜色值。

## 三、状态模型

### 1. Redux 状态定义

`src/store/modules/app.ts` 中与主题有关的字段如下：

```ts
interface AppState {
  themeMode: "light" | "dark" | "system";
  primaryColor: string;
  isDark: boolean;
  isGray: boolean;
  isColorWeak: boolean;
  // 其他布局和应用设置...
}
```

初始值为：

```ts
const initialState: AppState = {
  themeMode: "light",
  primaryColor: "rose",
  isDark: false,
  isGray: false,
  isColorWeak: false,
  // ...
};
```

字段职责如下：

| 字段           | 含义                 | 来源              | 用途                                         |
| -------------- | -------------------- | ----------------- | -------------------------------------------- |
| `themeMode`    | 用户选择的模式       | `setThemeMode`    | 决定使用亮色、暗色或系统模式                 |
| `primaryColor` | 当前主题色名称       | `setPrimaryColor` | 决定根节点上的 `theme-*` 类名                |
| `isDark`       | 解析后的最终暗色结果 | `setIsDark`       | 记录 `system` 解析后的布尔值，供其他模块读取 |
| `isGray`       | 是否启用灰色滤镜     | `setAppState`     | 控制 `grayscale(100%)`                       |
| `isColorWeak`  | 是否启用色弱滤镜     | `setAppState`     | 控制 `invert(80%)`                           |

`themeMode` 是用户意图，`isDark` 是根据用户意图计算出的最终结果。例如：

```text
themeMode = system + 系统当前为 dark → isDark = true
 themeMode = system + 系统当前为 light → isDark = false
 themeMode = dark                         → isDark = true
 themeMode = light                        → isDark = false
```

### 2. 持久化方式

应用 reducer 使用以下配置持久化：

```ts
const appPersistConfig = {
  key: "shadmin-app",
  storage,
  version: 1,
};
```

`appPersistedReducer` 被注册到 `src/store/index.ts` 的 root reducer 中，`storage` 来自 `redux-persist/lib/storage`，实际使用浏览器 localStorage。

应用入口通过 `StoreProvider` 和 `PersistGate` 包裹路由：

```tsx
<ReduxProvider store={store}>
  <PersistGate
    loading={<FullScreenLoader open text="Loading..." />}
    persistor={persistor}
  >
    {children}
  </PersistGate>
</ReduxProvider>
```

因此用户修改的主题模式、主题色、灰色模式和色弱模式会随 app 状态一并保存。刷新页面时，`PersistGate` 会等待状态恢复后再渲染应用，随后 `ThemeProvider` 根据恢复后的配置更新 DOM。

### 3. action 和 selector

主题相关 action：

```ts
setThemeMode(state, action: PayloadAction<AppState['themeMode']>) {
  state.themeMode = action.payload
}

setPrimaryColor(state, action: PayloadAction<string>) {
  state.primaryColor = action.payload
}

setIsDark(state, action: PayloadAction<boolean>) {
  state.isDark = action.payload
}

setAppState(state, action: PayloadAction<Partial<AppState>>) {
  return { ...state, ...action.payload }
}
```

主题相关 selector：

```ts
selectThemeMode: (app) => app.themeMode;
selectPrimaryColor: (app) => app.primaryColor;
selectIsDark: (app) => app.isDark;
```

`GraySwitcher` 和 `WeakSwitcher` 没有单独的 reducer，而是通过通用 action 修改：

```ts
dispatch(setAppState({ isGray: checked }));
dispatch(setAppState({ isColorWeak: checked }));
```

## 四、CSS 主题系统

### 1. 基础语义化变量

`src/index.css` 定义了基础 CSS 变量，并通过 Tailwind v4 的 `@theme inline` 将变量映射为工具类：

```css
@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --color-primary: var(--primary);
  --color-primary-foreground: var(--primary-foreground);
  --color-card: var(--card);
  --color-border: var(--border);
  --color-input: var(--input);
  --color-muted: var(--muted);
  --color-ring: var(--ring);
}
```

基础亮色变量位于 `:root`：

```css
:root {
  --background: oklch(1 0 0);
  --foreground: oklch(0.145 0 0);
  --primary: oklch(0.205 0 0);
  --primary-foreground: oklch(0.985 0 0);
  --card: oklch(1 0 0);
  --border: oklch(0.922 0 0);
  /* 还包括 secondary、muted、accent、destructive、chart、sidebar 等变量 */
}
```

组件不直接使用 `oklch(...)`，而是使用语义化 class：

```tsx
<div className="bg-background text-foreground">
  <button className="bg-primary text-primary-foreground">操作</button>
</div>
```

这样切换主题时只需要更新变量，不需要修改每个组件。

### 2. 暗色变量

暗色变量定义在 `.dark` 选择器下：

```css
.dark {
  --background: oklch(0.145 0 0);
  --foreground: oklch(0.985 0 0);
  --card: oklch(0.205 0 0);
  --card-foreground: oklch(0.985 0 0);
  --primary: oklch(0.922 0 0);
  --primary-foreground: oklch(0.205 0 0);
  /* 还包括 secondary、muted、accent、border、sidebar 等暗色变量 */
}
```

主题切换并不修改 React 组件的 props，而是给 `document.documentElement` 添加或删除 `dark`：

```ts
const root = document.documentElement;

root.classList.add("dark");
root.classList.remove("dark");
```

CSS 中的 `.dark` 变量会立即覆盖 `:root` 的同名变量。

### 3. Tailwind 暗色变体

文件顶部定义了自定义暗色变体：

```css
@custom-variant dark (&:is(.dark *));
```

因此组件可以使用：

```tsx
<div className="bg-white dark:bg-black" />
```

项目中的大量 UI 组件还使用了 `dark:` 变体，例如暗色边框、输入框、弹窗和 hover 状态。主题模式只负责设置 `.dark`，具体颜色由 CSS 变量和 Tailwind 变体共同完成。

### 4. 主题色变量

主题色不是动态创建 CSS，而是在 `src/index.css` 中预先写好多套变量。每套主题同时包含亮色和暗色规则：

```css
:root.theme-rose {
  --primary: oklch(0.645 0.246 16.439);
  --primary-foreground: oklch(0.969 0.015 12.422);
  /* 还包括 background、card、border、chart、sidebar 等变量 */
}

.dark.theme-rose {
  --primary: oklch(0.645 0.246 16.439);
  --primary-foreground: oklch(0.969 0.015 12.422);
  /* 暗色下的变量 */
}
```

当前 CSS 中存在以下主题色：

```text
blue
orange
green
rose
doom
pink
mocha
nature
neo
```

主题色规则使用 `:root.theme-{name}` 和 `.dark.theme-{name}`，因为类名会加到同一个 `document.documentElement` 上：

```html
<html class="dark theme-blue"></html>
```

### 5. 主题色切换的清理策略

`changeColorClass` 每次先移除所有已知主题色，再添加当前主题色：

```ts
export function changeColorClass(color: string) {
  const root = document.documentElement;
  const themeArr = [
    "theme-blue",
    "theme-orange",
    "theme-green",
    "theme-rose",
    "theme-doom",
    "theme-pink",
    "theme-mocha",
    "theme-nature",
    "theme-neo",
  ];

  root.classList.remove(...themeArr);

  if (color) {
    root.classList.add(`theme-${color}`);
  }
}
```

这样可以保证根节点同时最多只有一个 `theme-*` 类，避免多个主题的 CSS 选择器互相覆盖。

新增主题色时，必须同时完成：

1. 在 CSS 中增加 `:root.theme-{name}`；
2. 增加 `.dark.theme-{name}`；
3. 将名称加入 `changeColorClass` 的清理数组；
4. 在颜色选择器中增加选项；
5. 将初始值或类型限制更新为有效名称；
6. 分别验证亮色和暗色下的背景、文字、边框、图表和侧边栏。

## 五、主题工具函数

文件：`src/features/theme/shared.ts`。

### 1. `changeThemeClassName`

职责是将最终的暗色布尔值转换成根节点 class：

```ts
export function changeThemeClassName(isDark: boolean) {
  const root = document.documentElement;

  if (isDark) {
    root.classList.add("dark");
  } else {
    root.classList.remove("dark");
  }
}
```

它不负责判断用户选择，也不负责 Redux，只处理 DOM 类名。

### 2. `getSystemThemeMode`

通过浏览器媒体查询获取当前系统偏好：

```ts
export function getSystemThemeMode(): "light" | "dark" {
  const isDark = window.matchMedia("(prefers-color-scheme: dark)").matches;
  return isDark ? "dark" : "light";
}
```

当用户选择 `system` 时，`ThemeProvider` 调用它决定最终使用亮色还是暗色。

### 3. `getSystemReduce`

通过媒体查询判断用户是否偏好减少动画：

```ts
export function getSystemReduce(): boolean {
  return window.matchMedia("(prefers-reduced-motion: reduce)").matches;
}
```

如果返回 `true`，主题切换会跳过 View Transition 动画，直接切换 `dark` 类。

### 4. `isClassNameDark`

读取 DOM 当前状态：

```ts
export function isClassNameDark(): boolean {
  return document.documentElement.classList.contains("dark");
}
```

`applyThemeMode` 使用它判断当前 DOM 是否已经是目标状态，避免重复操作和重复动画。

### 5. `applyThemeMode`

这是暗色切换的核心函数，流程如下：

```text
接收目标 isDark
    ↓
检查根节点是否已经有相同 dark 状态
    ↓ 相同
直接返回
    ↓ 不同
检查 prefers-reduced-motion
    ↓ 是
直接添加/删除 dark
    ↓ 否
document.startViewTransition
    ↓
在过渡回调中添加/删除 dark
    ↓
transition.ready 后执行圆形 clip-path 动画
```

核心实现：

```ts
export function applyThemeMode(isDark: boolean) {
  if (isDark === isClassNameDark()) {
    return;
  }

  const isReduce = getSystemReduce();
  if (isReduce) {
    changeThemeClassName(isDark);
    return;
  }

  const transition = document.startViewTransition(() => {
    changeThemeClassName(isDark);
  });

  const x = innerWidth;
  const y = 0;
  const endRadius = Math.hypot(innerWidth, innerHeight);

  transition.ready.then(() => {
    const clipPath = [
      `circle(0px at ${x}px ${y}px)`,
      `circle(${endRadius}px at ${x}px ${y}px)`,
    ];

    document.documentElement.animate(
      {
        clipPath: isDark ? [...clipPath].reverse() : clipPath,
      },
      {
        duration: 300,
        easing: "ease-out",
        pseudoElement: isDark
          ? "::view-transition-old(root)"
          : "::view-transition-new(root)",
      },
    );
  });
}
```

动画起点是屏幕右上角：

```ts
const x = innerWidth;
const y = 0;
```

结束半径使用视口宽高计算出的最远距离，保证圆形扩散覆盖整个页面。进入暗色和退出暗色时通过反转 `clipPath` 数组实现不同的动画方向。

## 六、ThemeProvider 的实现

文件：`src/features/theme/ThemeProvider.tsx`。

它虽然命名为 Provider，但没有创建 React Context，实际职责是一个“主题状态副作用同步组件”：

1. 从 Redux 读取主题设置；
2. 把 `themeMode` 解析为 `isDark`；
3. 写回 `app.isDark`；
4. 修改根节点 `dark` 类名；
5. 修改根节点主题色类名；
6. 修改根节点滤镜样式。

### 1. 读取 Redux 状态

```tsx
const dispatch = useAppDispatch();
const themeMode = useAppSelector(selectThemeMode);
const isGray = useAppSelector((state) => state.app.isGray);
const isColorWeak = useAppSelector((state) => state.app.isColorWeak);
const primaryColor = useAppSelector(selectPrimaryColor);
```

它直接依赖 Redux Provider，因此必须挂载在 `StoreProvider` 内部。

### 2. 解析主题模式并应用暗色类

```tsx
useEffect(() => {
  let isDark: boolean;

  if (themeMode === "system") {
    isDark = getSystemThemeMode() === "dark";
  } else {
    isDark = themeMode === "dark";
  }

  dispatch(setIsDark(isDark));
  applyThemeMode(isDark);
}, [dispatch, themeMode]);
```

数据变化过程：

```text
themeMode = light → isDark = false → 删除 html.dark
 themeMode = dark → isDark = true  → 添加 html.dark
 themeMode = system → 查询系统媒体 → 添加或删除 html.dark
```

这里的 `isDark` 是派生状态：实际决定页面样式的是 DOM 上的 `dark` 类和 CSS 变量，Redux 中的 `isDark` 主要用于让其他模块读取当前解析结果。

### 3. 合并灰色和色弱滤镜

```tsx
useEffect(() => {
  const root = document.documentElement;
  const filters: string[] = [];

  if (isGray) filters.push("grayscale(100%)");
  if (isColorWeak) filters.push("invert(80%)");

  root.style.filter = filters.length > 0 ? filters.join(" ") : "none";
  root.style.transition = "filter 0.45s ease";
}, [isGray, isColorWeak]);
```

两个设置使用数组合并，而不是分别对 `root.style.filter` 赋值。这样同时开启时会得到：

```css
filter: grayscale(100%) invert(80%);
```

关闭其中一个模式时，另一个模式仍然保留。

### 4. 应用主题色

```tsx
useEffect(() => {
  changeColorClass(primaryColor);
}, [primaryColor]);
```

主题色切换只更新根节点 class，不需要重新渲染整个页面。

### 5. 返回 children

```tsx
return children;
```

它没有额外 DOM 节点，也没有 Context 值。这样不会改变页面布局和 CSS 选择器层级。

## 七、主题控件实现

### 1. 顶部循环切换按钮

文件：`src/features/theme/ThemeToggle.tsx`。

支持的模式顺序：

```ts
const themeModeSquences: ThemeMode[] = ["light", "dark", "system"];
```

组件初始化时从 Redux 读取当前模式；如果没有值，则使用 `system`：

```tsx
const [themeMode, setThemeMode] = useState<ThemeMode>(
  useAppSelector(selectThemeMode) || "system",
);
```

点击后的流程：

```tsx
const toggleThemeMode = (mode: ThemeMode) => {
  setThemeMode(mode);
  dispatch(setAppThemeMode(mode));
};

const handleToggle = () => {
  const index = themeModeSquences.findIndex((mode) => mode === themeMode);
  const nextIndex = (index + 1) % themeModeSquences.length;
  const nextThemeMode = themeModeSquences[nextIndex];
  toggleThemeMode(nextThemeMode);
};
```

按钮图标按照本地状态显示：

```tsx
{
  themeMode === "light" && <SunIcon />;
}
{
  themeMode === "dark" && <MoonIcon />;
}
{
  themeMode === "system" && <LaptopIcon />;
}
```

因此每次点击循环为：

```text
light → dark → system → light
```

该组件被顶部栏和登录页复用。

### 2. 设置面板的三态选择

文件：`src/features/theme/ThemeToggleGroups.tsx`。

它使用 `ToggleGroup` 展示三个互斥选项：

```tsx
<ToggleGroup
  type="single"
  value={appThemeMode}
  onValueChange={handleValueChange}
>
  <ToggleGroupItem value="light">
    <SunIcon />
  </ToggleGroupItem>
  <ToggleGroupItem value="dark">
    <MoonIcon />
  </ToggleGroupItem>
  <ToggleGroupItem value="system">
    <LaptopIcon />
  </ToggleGroupItem>
</ToggleGroup>
```

值变化后直接 dispatch：

```tsx
const handleValueChange = (value: string) => {
  dispatch(setThemeMode(value as ThemeMode));
};
```

Redux 更新后，`ThemeProvider` 的 effect 自动执行并应用主题。

### 3. 主题色选择器

文件：`src/components/settingSheet/presetColorToggle.tsx`。

每个主题色是一个 `ToggleGroupItem`，点击后派发颜色名称：

```tsx
const handlePresetColorChange = (color: string) => {
  dispatch(setPrimaryColor(color || ""));
};
```

选中状态通过 Redux 的 `primaryColor` 判断：

```tsx
<CheckIcon
  className={cn(primaryColor === "rose" ? "opacity-100" : "opacity-0")}
/>
```

当前界面展示的颜色包括：

```text
orange、blue、rose、green、pink、mocha、nature、neo
```

`doom` 的选项代码目前被注释，但 CSS 和 `changeColorClass` 仍支持 `doom`。因此“CSS 支持的主题色”和“设置面板实际可选的主题色”不是完全相同的集合。

### 4. 灰色模式

文件：`src/components/settingSheet/GraySwitcher.tsx`。

它是受控开关：

```tsx
const isGray = useAppSelector<boolean>((state) => state.app.isGray);

const handleCheckedChange = (checked: boolean) => {
  dispatch(setAppState({ isGray: checked }));
};

<Switch checked={isGray} onCheckedChange={handleCheckedChange} />;
```

Redux 状态更新后，`ThemeProvider` 会把 `isGray` 转换为根节点的 CSS filter。

### 5. 色弱模式

文件：`src/components/settingSheet/WeakSwitcher.tsx`。

实现与灰色模式一致，只是字段改为 `isColorWeak`：

```tsx
const isColorWeak = useAppSelector<boolean>((state) => state.app.isColorWeak);

dispatch(setAppState({ isColorWeak: checked }));
```

`ThemeProvider` 将其转换为 `invert(80%)`。

### 6. 主题设置面板

文件：`src/components/settingSheet/ThemeTabContent.tsx`。

该组件按顺序提供：

1. 暗色模式三态选择；
2. 主题色选择；
3. 灰色模式开关；
4. 色弱模式开关。

设置抽屉由 `src/components/settingSheet/index.tsx` 管理打开状态，并在 `Tabs` 的 `theme` 面板中挂载 `ThemeTabContent`。面板上的标题和描述通过 `react-i18next` 翻译：

```tsx
<FieldTitle>{t('settings.darkMode')}</FieldTitle>
<FieldDescription>
  {t('settings.darkModeDescription')}
</FieldDescription>
```

## 八、应用启动和挂载顺序

### 1. 入口层级

`src/main.tsx` 的实际挂载顺序是：

```tsx
<StrictMode>
  <StoreProvider>
    <QueryClientProvider client={queryClient}>
      <RouterProvider router={router} />
    </QueryClientProvider>
  </StoreProvider>
</StrictMode>
```

`ThemeProvider` 位于 `src/App.tsx`，路由渲染 `App` 后形成：

```text
StoreProvider
└── PersistGate
    └── QueryClientProvider
        └── RouterProvider
            └── App
                └── ThemeProvider
                    └── LanguageProvider
                        └── WatermarkProvider
                            └── 页面和布局
```

因此主题状态能够从 Redux 读取，且主题副作用会覆盖所有路由页面。

## 十、现有实现中的边界和注意事项

以下内容是从现有实现可以确认的行为，维护时需要特别注意。

### 1. `system` 模式不会持续监听系统变化

`ThemeProvider` 只在 `themeMode` 变化时执行 effect。选择 `system` 后，如果用户在操作系统设置中切换亮色/暗色，当前代码没有注册 `matchMedia(...).addEventListener('change', ...)`，因此页面不一定会立即更新。

如果需要实时跟随系统，应在 `themeMode === 'system'` 时监听：

```tsx
useEffect(() => {
  const media = window.matchMedia("(prefers-color-scheme: dark)");

  const apply = () => {
    const isDark =
      themeMode === "dark" || (themeMode === "system" && media.matches);

    dispatch(setIsDark(isDark));
    applyThemeMode(isDark);
  };

  apply();

  if (themeMode === "system") {
    media.addEventListener("change", apply);
  }

  return () => media.removeEventListener("change", apply);
}, [dispatch, themeMode]);
```

### 2. `ThemeToggle` 使用本地 state

`ThemeToggle` 初始化时从 Redux 读取 `themeMode`，之后主要依赖自己的 `themeMode` state。设置面板中的 `ThemeButtonGroups` 修改 Redux 后，顶部的 `ThemeToggle` 本地图标可能不会同步更新。

更稳定的方案是直接使用 Redux selector 作为唯一数据源：

```tsx
const themeMode = useAppSelector(selectThemeMode) || "system";

const toggleThemeMode = (mode: ThemeMode) => {
  dispatch(setAppThemeMode(mode));
};
```

如果保留本地 state，则需要监听 Redux 的 `themeMode` 并同步更新。

### 3. `ToggleGroup` 可能产生空字符串

单选 `ToggleGroup` 的某些行为可能允许取消当前选项，`onValueChange` 可能收到 `''`。当前代码直接把 string 转换为 `ThemeMode`：

```tsx
dispatch(setThemeMode(value as ThemeMode));
```

更安全的处理方式是校验 value：

```tsx
const handleValueChange = (value: string) => {
  if (value === "light" || value === "dark" || value === "system") {
    dispatch(setThemeMode(value));
  }
};
```

### 4. 主题色选择器的受控状态需要统一

`PresetColorToggle` 使用 `primaryColor` 判断 CheckIcon 是否显示，但 `ToggleGroup` 使用的是 `defaultValue="top"`，并没有把 `primaryColor` 传给 `value`。这会造成组件内部选中值和 Redux 值存在不同步的可能。

建议改为受控组件：

```tsx
<ToggleGroup
  type="single"
  value={primaryColor}
  onValueChange={handlePresetColorChange}
>
  {/* options */}
</ToggleGroup>
```

### 5. `document.startViewTransition` 需要兼容性处理

当前代码直接调用：

```ts
document.startViewTransition(() => {
  changeThemeClassName(isDark);
});
```

不支持 View Transition API 的浏览器可能抛出异常。需要兼容旧浏览器时，应先检测：

```ts
if (!("startViewTransition" in document)) {
  changeThemeClassName(isDark);
  return;
}
```

同时建议处理 `transition.ready` 的 reject，避免动画失败产生未处理 Promise。

### 6. 首屏主题闪烁

当前主题类名由 React 挂载后的 `useEffect` 添加。虽然 `PersistGate` 会等待 Redux 恢复，但根节点在 React effect 执行前仍可能短暂使用默认 CSS。

如果需要消除首屏闪烁，可以在 HTML 模板中增加极小的初始化脚本：

1. 读取持久化的 `themeMode`；
2. 查询系统模式；
3. 在首屏绘制前给 `<html>` 添加 `dark`；
4. React 挂载后由 ThemeProvider 接管后续更新。

该方案需要与 redux-persist 的存储结构保持一致，修改持久化 key 时要同步修改脚本。

### 7. `next-themes` 不是当前主题的实际控制器

项目依赖中包含 `next-themes`，但主题切换实际由 `src/features/theme/ThemeProvider.tsx` 和 Redux 实现，没有使用 `next-themes` 的 `ThemeProvider`。

`src/components/ui/sonner.tsx` 中使用了：

```tsx
const { theme = "system" } = useTheme();
```

但应用没有挂载 `next-themes` 的 Provider。这样 Sonner 的 `theme` 可能始终使用默认值，而不是项目 Redux 中的 `themeMode`。如果希望 Toast 与应用主题严格同步，应统一主题来源，不要让两个主题系统并存。

### 8. `isDark` 是持久化字段，但本质是派生值

`isDark` 会被保存到 Redux，但它取决于 `themeMode` 和系统当前状态。对于 `system` 模式，持久化后的 `isDark` 可能与下一次启动时的系统状态不同。

实际使用时应以 `themeMode` 重新计算结果为准；如果没有其他模块必须读取 Redux `isDark`，可以考虑不持久化它，或者在 rehydrate 后立即重新计算。

### 9. 滤镜作用于整个根节点

`filter` 设置在 `document.documentElement` 上，会影响整个页面，包括文字、图片、弹窗和可能挂载到 body 的 Portal。尤其是 `invert(80%)` 并不是严格意义上的色弱模拟，只是视觉反转效果。

如果只希望影响业务内容，应将滤镜加到应用内容容器，而不是 `html`。如果继续作用于根节点，应验证弹窗、Toast、图片和二维码等内容是否仍可用。

### 10. 主题色名称目前是普通 string

`primaryColor` 当前类型为 `string`，因此可以 dispatch 任意值。只有 CSS 有对应规则时，页面才会看到预期效果。后续可以将它收窄为主题色联合类型：

```ts
type PrimaryColor =
  | "blue"
  | "orange"
  | "green"
  | "rose"
  | "doom"
  | "pink"
  | "mocha"
  | "nature"
  | "neo";
```

这样新增或删除主题时，TypeScript 可以帮助检查所有选择器和映射。

## 十三、结论

该项目的主题系统以 Redux 为配置中心，以 `ThemeProvider` 为副作用同步层，以 `document.documentElement` 上的 `dark` 和 `theme-*` 类为 CSS 入口，以 CSS 变量为具体视觉实现。

主题模式、主题色、灰色模式和色弱模式共享同一套持久化状态，但各自通过独立的 effect 更新 DOM。后续扩展时，应继续保持“控件只修改状态、Provider 统一执行副作用、CSS 使用语义化变量”的边界，避免在业务组件中直接操作根节点 class 或重复实现主题判断。
